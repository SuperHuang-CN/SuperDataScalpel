# DataScalpel 前端开发约定

本文件适用于 `data-scalpel-ui` 下的所有代码。目标是让前端与后端保持一致的模块化单体结构，使业务代码容易定位、修改和测试。

## 技术基线

- 使用 React、TypeScript、Vite、React Router、Ant Design、TanStack Query 和 AntV X6。
- Ant Design 是全局 UI 组件体系。普通管理页面优先使用其 Table、Form、Drawer、Modal、Tree、Select 等组件。
- 未经用户确认，不引入 Tailwind CSS、shadcn/ui、Redux、其他全局 UI 框架或全局状态框架。
- 保持一个 Vite 应用，不拆微前端，也不将业务模块拆成独立 npm 包。

## 目录结构

前端源码按照以下三层组织：

```text
src/
├── app/       # 应用装配：路由、布局、全局 Provider 和启动配置
├── modules/   # 按业务域组织的业务代码
└── shared/    # 与具体业务无关、可被多个业务域复用的基础能力
```

- `app` 只负责应用装配，不放具体业务页面和业务规则。
- `modules` 按系统管理、数据源管理、模型管理、任务管理、数据服务等业务域划分。
- `shared` 只存放真正跨业务通用的 API 基础设施、统一查询、通用组件、类型和工具；不得成为无法归类代码的收纳目录。
- 页面、接口、业务组件、业务 Hook 和业务类型应跟随所属业务模块存放，不建立全局的 `pages`、`services` 或业务组件大仓库。

业务模块内部优先采用一致的结构：

```text
modules/<module>/
├── api/          # 本模块接口与接口类型
├── components/   # 本模块复用的业务组件
├── pages/        # 路由页面
├── hooks/        # 本模块业务 Hook
├── model/        # 前端业务类型、常量和数据转换
└── index.ts      # 提供给其他业务模块的公开入口
```

目录按实际需要创建。没有内容时，不为保持形式完整而创建空目录或空层级。

## 依赖方向

- 基本依赖方向为 `app -> modules -> shared`。
- `shared` 不得依赖 `modules` 或 `app`。
- 业务域之间存在真实耦合时允许直接协作，例如任务模块使用数据源选择器和模型选择器。
- 一个业务模块引用另一个业务模块时，只能通过对方的 `index.ts` 公开入口，不得导入对方内部文件。
- 不为了形式上的模块解耦引入事件总线、消息机制、重复 DTO 或额外适配层。
- 只有被至少两个业务域实际复用、且不含特定业务语义的代码，才应移动到 `shared`。

## 路由与页面

- 顶层路由在 `app` 中统一装配，具体页面实现放在对应业务模块的 `pages` 中。
- 体积较大的页面能力应按路由懒加载，任务编排器和 Monaco 编辑器不得进入普通首页的首屏包。
- 页面组件负责组合查询、表格、表单和业务组件；复杂业务处理应下沉到所属模块的 Hook、model 或专用组件。

## API 与统一查询

- HTTP 客户端、统一错误转换和请求拦截能力放在 `shared/api`，业务模块不得各自创建 HTTP 客户端。
- 后端成功响应直接消费明确 DTO 或 `PageResponse`，不得在前端假定或自行引入 `Result<T>`、`ApiResponse<T>` 等成功响应包裹层。
- 所有 API 错误均按 RFC 9457 Problem Details 消费。`ApiError` 必须保留完整 `problem`（包括稳定 `code`、`instance` 和字段校验 `violations`）；页面优先显示 `detail`，需要差异化交互时依据 `code`，不得各模块自行解析错误响应。
- 具体字段与状态码约定见根目录 [后端 API 响应与异常处理](../docs/design/backend-api-response-and-error-handling.md)；修改前后端错误契约时必须同步更新该文档，相关测试要求当前暂时禁用。
- 常规列表查询应与后台统一 Search API 对应。`SearchRequest`、操作符、条件组合、分页和排序等通用类型及构造能力放在 `shared/search`。
- 业务模块只声明本业务可查询字段、页面筛选项和接口地址，不重复实现通用 SearchRequest 组装逻辑。
- TanStack Query 的 query key 应稳定、可序列化，并包含会影响响应结果的查询参数。
- API 响应类型必须明确，禁止使用 `any` 绕过接口契约。

## 状态管理

- 服务端数据、缓存、重新加载和请求状态统一由 TanStack Query 管理。
- 表单状态使用 Ant Design Form，普通页面交互状态优先使用 React 自身状态。
- 跨页面共享状态只有在出现明确需求后再设计；不得预先建立全局 Store。
- 不要把服务端数据复制到全局状态或长期同步维护两份数据。

## 浏览器自动填充

- 只有登录表单允许启用浏览器自动填充；登录用户名和密码分别使用 `username`、`current-password` 语义。
- 登录页的自动填充视觉必须作用于完整输入框容器，使前缀图标、输入内容和密码可见按钮保持同一背景；不得只保留浏览器施加在内部 `input` 上的分段底色。自动填充状态仍需保留清晰文字、光标和焦点边框。
- 其他生产表单必须设置 `autoComplete="off"`，包括查询栏、抽屉、弹窗、编辑器和 Canvas 节点配置表单。
- 数据源密码、访问 Token、API Key、用户初始/重置密码等非登录页敏感值统一使用共享 `BusinessSecretInput`：DOM 保持普通业务字段语义，视觉默认掩码并提供明确的显示/隐藏按钮，同时设置 `autoComplete="off"` 和稳定、领域化的 DOM `name`，避免浏览器把相邻地址、账号和业务密钥误识别为登录凭据。不得在这些表单中继续直接使用 `Input.Password`，也不得使用 `new-password`、`current-password` 或成对的 `username`、`password` DOM 名称。Ant Design `Form.Item name` 和对外请求字段仍按业务契约命名。
- 不得使用隐藏诱饵输入、随机字段名、聚焦后解除 `readonly` 等欺骗浏览器的方案。需要兼容第三方密码管理器时必须先明确目标产品和取舍，不得默认加入厂商私有属性。

## Canvas 约定

- 任务编排 Canvas 属于任务业务，代码应放在 `modules/task/canvas`，不作为全局业务无关能力放入 `shared`。
- AntV X6 只负责图形编辑和交互。保存到后端的是稳定的节点、端口、连线和配置 JSON，不得直接持久化 X6 内部对象。
- 节点定义、节点配置和序列化结果必须具有明确的 TypeScript 类型，不得扩散 `any`。
- 新增节点必须在独立节点目录中通过 `CanvasNodeSpec` 接入，声明协议版本、分类、二级分组、模式、图能力、默认配置、解析器、安全摘要、元数据引用和动态 Inspector；不得继续扩张 Inspector、定义 IO、端口或摘要中的大型节点类型 `switch`。
- X6 使用通用运行时 Shape；节点 Shape、图标、分类、分组和模式能力属于设计器运行数据，不得进入稳定 Canvas JSON。
- 节点元数据依赖通过资源种类的 Metadata Provider 扩展，不得按节点类型在统一 Hook 中复制查询分支；同一资源引用必须去重，并保留全部受影响节点 ID。
- 公共 Canvas 表单组件只有在至少两个现有节点真实复用时才可抽取；不得建设配置驱动的万能表单。
- 前端 Registry 的图规则只用于即时交互提示，不能替代 Task Engine 对 Schema、执行模式、有界性和业务配置的权威校验。
- 节点配置面板的上游表和字段候选必须使用 Task Engine 编译结果中的 `inputTables`，不得在前端另写 Schema 传播逻辑。当前节点存在错误时，只要 Compiler 仍返回可用输入上下文，Inspector 就必须继续展示这些候选，允许用户完成或修正配置。
- 上游变化导致已保存选项失效时必须保留原值并明确标记不可用，不得静默清空、自动改名或用前端推测结果覆盖 Compiler 响应。Compiler 暂不可用时应展示等待或失败状态，不得把空响应解释为上游没有表。
- Canvas Inspector 以紧凑、可连续完成配置为目标。普通配置项、字段校验错误、已失效配置和当前必须处理的执行风险直接展示；目标资源详情、格式协议、执行语义、完整物理路径等低频只读信息不得常驻，应放在字段标题旁的 Tooltip、带 `aria-label` 的图标按钮或 Modal 中按需查看。
- 仅在当前模式或选项下生效的配置必须条件渲染。字段映射、规则列表等重复结构优先使用紧凑行或表格式布局，不得为每一项堆叠高标题 Card；辅助说明不能通过大量 Collapse 制造新的操作层级，错误和危险操作也不得为了节省空间被隐藏。
- 修改连线、环路、端口、删除、复制、撤销重做或序列化行为时，补充单元测试或端到端测试的要求当前暂时禁用。

## 组件与代码风格

- 应用顶部使用面包屑表达当前位置。普通列表页不得再重复放置“页面大标题、资源数量、说明文字”组成的独立标题区；资源名称与总数放在结果工具栏，避免标题区占用纵向空间。普通页面默认使用 12～16px 内容边距；Canvas、代码编辑器等专业工作区可根据交互需要例外处理。
- 普通列表页内部依次为“筛选工具带、结果区域”。筛选工具带是独立面板；结果工具栏、局部提示、表格和分页合并为一个完整结果面板。不额外放置大标题、筛选标题或说明区。
- 普通管理表格应占满页面剩余高度：页面主体不产生纵向滚动，表头和分页保持可见，数据行在表体区域内部滚动。Canvas、代码编辑器等专业工作区单独设计滚动边界。
- 优先复用 Ant Design 和已有工程组件，不为简单样式重复封装基础组件。
- 业务组件放在所属模块；只有无业务语义且确实跨模块复用的组件才放入 `shared/components`。
- 优先使用明确的小组件和小函数，避免单个页面同时承担接口访问、复杂转换、Canvas 操作和大量渲染逻辑。
- 新代码保持严格 TypeScript 类型，不使用无理由的类型断言、`@ts-ignore` 或 `eslint-disable`。
- 命名应表达业务含义，避免 `common`、`misc`、`helper` 等含义模糊的目录或文件名。
- 全前端禁止使用全宽、大面积、持续占位的 Alert、Banner 或自定义色块承载帮助说明、运行语义、普通警告或局部错误。帮助信息必须贴近其解释的标题、字段、状态或操作：一两句使用 Tooltip，包含多段、列表或处理语义的内容使用 Popover；入口必须同时支持 Hover、键盘 Focus、触屏 Click 和明确的 `aria-label`。
- 常规异步错误、停用/只读/权限不足、数据截断等局部状态使用紧凑的图标加简短结论，详细错误和处理建议按需通过 Tooltip/Popover 查看；错误是否存在及可执行的重试/修复操作必须直接可见，不能只藏在 Hover 中。共享场景复用 `ContextHelp`、`InlineFeedback` 和 `CompactAlert`，不得重新引入大块提示区。
- 阻断校验、危险确认、数据丢失风险和整个内容区域不可用仍须直接可见，但必须位于对应业务上下文内并保持紧凑；优先使用 Form.Item 校验、局部反馈或替代内容错误态，不得为了压缩空间删除原有错误详情、重试入口或确认信息。

## 普通管理页面交互

### 顶级管理页视觉语言

- 顶级管理页采用克制的蓝紫未来感：应用工作区使用淡蓝至淡紫渐变，主侧栏使用深钴蓝至靛蓝渐变；不得引入大型纯装饰 3D 元素占用数据空间。
- 查询面板、目录面板和结果面板使用半透明白色材质、低对比度边框、柔和阴影与适量背景模糊建立层级。浏览器不支持背景模糊时必须回退为不透明白色，不能影响可读性。
- Panel 阴影统一分为三档：页面级查询、目录、结果、详情身份头和完整工作台使用标准阴影；详情信息分区、抽屉内部纸面和局部卡片使用更弱的内部阴影；Popover、Modal 等真实浮层才使用高层阴影。普通业务页面不得自行增加新的阴影参数组合。
- 相邻且连续的结果工具栏、表格、分页，以及 Drawer 的正文和底部操作栏不得分别投影；只允许最外层 Panel 投影，内部关系使用 `1px` 分隔线和背景层级表达。禁止使用大幅向下偏移的阴影形成横向灰色或紫色带。
- 查询面板与结果面板相互独立；结果工具栏、表格和分页必须保持为一个整体。不得在结果面板内部继续堆叠无业务意义的玻璃 Card。
- 外层面板默认使用 14～16px 圆角，普通控件、菜单选中项和资源图标块使用 8～10px 圆角。渐变、圆角和阴影应保持克制，不能削弱信息密度或状态辨识度。
- 普通资源列表的主身份列使用 32～36px 的低饱和单色图标块辅助识别；调用排行、异常明细等统计表保持紧凑并省略资源图标。状态使用语义明确的轻量圆角徽标，不得只靠颜色表达含义。
- 第五种视觉通过明确页面作用域扩展到顶级管理页、业务详情页、数据服务全页编辑器、首页、登录页和非 Canvas 业务覆盖层；各作用域只能共享视觉变量和窄职责 CSS 契约，不得用无边界全局选择器重写其他页面。
- 动效限于短时颜色、阴影和轻微位移过渡；必须尊重 `prefers-reduced-motion`。文字、键盘焦点和状态颜色需要满足可辨识性要求。
- 视觉升级不得破坏 1920×1080、100% 缩放下无页面横向滚动的目标，也不得改变双行语义合并、显式查询、固定表头与分页等交互规范。

### 详情页视觉

- 文件数据集、码表、模型、任务和数据服务等业务详情统一使用“玻璃身份头 + 完整页签内容面板”。身份头约 72px，使用半透明白色、14～16px 圆角、柔和阴影和适量背景模糊；不得再增加独立大标题或无业务意义的指标卡。
- 身份头左侧依次为返回入口、40px 低饱和资源图标块、名称、编码、状态和辅助信息；右侧保留刷新、修改、生命周期操作及更多菜单。最多一个主业务操作使用蓝紫渐变，长名称、多状态和多操作时必须允许合理收缩或换行，不能造成页面横向滚动。
- 页签导航约 48px，使用淡蓝紫选中背景和渐变强调线；页签内容是一个完整面板。完整详情页中的静态属性、配置、运行摘要和业务说明必须使用独立信息分区面板：14px 圆角、低对比度蓝紫边框、柔和阴影以及约 52～56px 的标题栏。左侧 3px 蓝紫渐变强调线只能位于标题栏内，不得贯穿正文内容。每个分区必须提供 36px 低饱和蓝紫图标块、明确标题和一句简短辅助说明，不得只放孤立的加粗标题。
- 同一详情页及全局详情信息分区统一使用同一套蓝紫强调线、图标块、边框和面板背景，不得用蓝、紫、青、橙等任意颜色区分业务分区。语义色只用于真实的成功、警告、错误、处理中等状态反馈，不能作为分区装饰色。
- 详情信息分区的静态属性统一使用共享信息网格：每个字段是独立的“弱标签 / 强内容”语义单元，标签约 12px 蓝灰色并直接位于约 14px 深色内容上方。不得使用 `bordered Descriptions` 形成整行标签色带、标签行与内容行分离的传统表格结构，也不得通过条纹背景模拟表头。宽屏基础标识默认四列，连接、运行和资源配置默认三列，中等窗口降为两列，小窗口降为单列；长说明、错误摘要和物理地址应合理跨列，普通末尾字段不得被组件自动拉伸为整行。
- 分区关系通过间距、边框、标题层级和柔和阴影建立，不得堆叠厚重描边、多层玻璃 Card 或大面积渐变。表格、代码块、状态反馈和 Empty 可以作为分区内容，但不得再包一层无业务意义的 Card；表格、代码编辑器、Canvas、抽屉和弹窗按自身密度单独处理，不得机械套用详情信息分区。
- 完整详情页的页签内容与信息分区使用统一空间节奏：页签栏到首个分区 `12px`，分区左右内缩 `12px`，相邻分区间距 `12px`，最后一个分区到页签容器底部 `16px`。该留白必须由共享页签内容层统一提供，各业务页面不得重复声明或叠加 padding；Canvas、任务定义编辑器和其他专业工作区保持零留白或使用自身独立契约。
- 详情页内带分页的关联列表、运行记录和日志表格使用顶部紧凑结果栏：左侧显示列表名称和总数，右侧将必要业务操作与“每页条数、简洁页码、刷新”分页控制分组展示；表格不得再占用独立底部分页行。无法提供总数的顺序分页也必须在顶部显示当前页、上一页和下一页，不得保留自定义底部分页。筛选条件留在左侧，查询和重置固定在筛选工具栏最右侧；该规则只适用于详情页嵌入式表格，顶级管理列表继续使用固定底部分页。
- 详情页嵌入式表格的筛选区统一使用约 `54px` 高的独立淡蓝紫半透明工具带，具有 `12～14px` 圆角、低对比度边框和极轻阴影；与结果区域保持约 `12px` 间距。筛选项不得保留“名称、状态、模式”等外置 `Form.Item` 标签：主搜索框使用搜索图标和具体的名称/编码占位文案，枚举控件使用“全部状态、全部类型”等自解释占位文案。查询使用克制的蓝紫渐变主按钮，重置使用低干扰文字按钮，两者固定在最右侧；刷新和分页属于结果栏，不得混入筛选操作。窄窗口允许工具带内部换行，但不得造成页面横向滚动。
- 任务详情只统一外层身份头、页签和普通内容；Canvas 定义编辑器、画布、节点面板和 Canvas 内部组件必须保持独立视觉边界，后续单独设计。

### 业务 Drawer、Modal 与表单

- 所有非 Canvas 业务 Drawer 和 Modal 必须增加统一 portal 作用域 class。共享样式只能通过该 class 生效，不得全局覆盖所有 Ant Design 覆盖层；Canvas 与任务编排覆盖层明确排除。
- Drawer 应先按业务复杂度选择结构，不得机械套用同一个大表单：单一配置或少量字段使用约 560～680px 的轻量纸面；普通资源使用约 680～820px、1～3 个明确业务分区；包含大量条件分支、连接参数或运行策略的复杂对象使用约 920～1120px 工作台，确有连续步骤时才增加左侧步骤导航；以筛选和批量勾选为核心的登记类操作应让表格成为主要工作区。不得为了显得“高级”给简单对象增加空步骤、无意义导航或大面积留白。
- Drawer 使用轻靛蓝遮罩、约 2px 背景模糊、淡蓝紫玻璃标题栏、白色主体和固定白色底部操作栏；右侧抽屉使用 16～18px 左侧圆角和柔和左侧阴影。标题栏左侧必须是与资源语义一致的图标块，旁边依次放主标题和一句短说明；状态、类型或模式放在标题栏右侧，不能让图标漂到标题右侧或把多个普通字段塞进标题栏。
- Modal 使用 16px 圆角、淡蓝紫标题区、清晰白色主体和带分隔线的底部操作区。危险确认继续使用红色语义、明确资源名称和二次确认，不得因为视觉统一弱化危险提示。
- 表单控件使用 8px 圆角、清晰边框和蓝紫焦点环；主按钮可使用蓝紫渐变，次要按钮保持浅色。长表单沿用现有分区与两列布局，分区使用白色纸面或淡紫辅助背景，不堆叠多层玻璃 Card。每个分区必须按业务任务命名并配合短说明，字段顺序应遵循“身份 → 业务配置 → 高级/保护配置”，不得按 DTO 字段顺序机械排列。
- 启用、推荐、注册等影响整个分区的布尔状态优先放在对应分区标题栏右侧，与普通输入字段分离；仅影响单个字段的开关仍留在字段上下文内。状态位置必须固定，不能因新增态、修改态或条件分支造成标题和输入列抖动。
- 底部操作栏左侧显示当前对象、选择数量、配置模式或保存后的后续动作等紧凑业务上下文，右侧保持“取消 + 唯一主操作”；不得在底栏并排堆积多个同级主按钮。异步操作继续保留 loading 和防重复提交。
- API Key、Token 等可选凭据优先使用“未配置 / 已保存”的直接状态和“配置 / 替换”操作按需展开输入框，避免密码管理器在抽屉打开时误填普通字段。该交互不得使用隐藏诱饵输入、随机字段名、焦点后解除只读等欺骗方案；展开后的凭据字段仍须遵守本文件的自动填充与 DOM 命名约定。
- 数据源配置等包含多个分区的复杂业务 Drawer 采用“清透精密玻璃工作台”作为基准：标题区必须具备资源图标、主标题、辅助说明和紧凑状态；左侧使用带编号与连接关系的浅色步骤导航；右侧分区采用统一白色玻璃纸面、低对比度蓝紫边框、柔和双层阴影和图标标题栏。此类复杂配置抽屉的输入控件可在自身作用域内使用约 `40px` 舒适高度，不得修改全局组件尺寸。用途或模式等少量互斥/多选项可使用低饱和图标选择卡，底部操作栏保持半透明且固定可见。上述装饰统一使用蓝紫中性色，语义色仅用于真实状态，不得为不同分区随意更换装饰色。
- 视觉调整不得改变 Drawer/Modal 尺寸、字段、校验、权限、loading、确认、提交行为和嵌套业务流程；复杂抽屉只调整外壳、分区、导航和表格视觉。

### 全页编辑器、首页与登录

- 数据服务新增和编辑路由由应用外壳提供专用全高工作区，不得依赖负 margin 抵消页面边距。顶部使用圆角玻璃身份栏；标准服务表单放在居中的白色编辑面板，SQL 和脚本服务保持左侧约 340～360px 配置面板与右侧大型定义面板。
- Monaco、SQL 编辑器和脚本工作台的内部主题与交互不得由全局视觉样式改写，只统一外层容器、边框、圆角、阴影和分区导航。
- 首页使用渐变工作区、玻璃欢迎区和资源概览卡。没有现成统计数据时不得为视觉效果新增接口或伪造数据，文案应使用正式产品表达，不保留工程骨架或待开发占位语气。
- 登录页使用淡蓝紫渐变与 CSS 柔光背景、约 400px 居中玻璃卡和 48px 品牌图标；保留浏览器自动填充、测试账号提示和认证行为，不使用图片、大型 3D 装饰或高干扰动效。

### 应用外壳与全局菜单

- 顶部栏承载侧栏开关、面包屑、部署信息和用户操作。普通列表的筛选工具带直接位于顶部栏下方。
- 展开的二级菜单使用内嵌圆角分组面板：与侧栏边缘保留约 6～8px 间距，使用低对比度半透明深蓝背景、12px 圆角和极淡描边，不得形成大面积近黑色块。选中项使用 10px 低饱和蓝紫高亮，并将短竖向强调条收在选中项内部；侧栏全高外轮廓保持直边。

### 查询栏

- 查询区使用单行筛选工具带，不再单独设置“筛选条件”标题。不得为了展示全部条件无限增高筛选区。
- 页面级交互使用标准尺寸而不是全局小尺寸：顶级列表筛选控件、结果工具栏主要操作、详情头部操作、业务 Drawer/Modal 表单与底部操作、非 Canvas 全页编辑器表单统一为 `32px` 高、`14px` 字号。主要搜索框在宽屏下约 `300～320px`；筛选工具带最小高度约 `60px`、控件间距约 `10px`。
- 表格行内操作、分页、目录树操作、Canvas Inspector 和其他高密度编辑器继续使用 `24～28px` 紧凑尺寸。不得通过修改全局 `componentSize` 一起放大；新增页面必须通过明确的页面或业务容器作用域选择标准尺寸，并为其中的 Table、Pagination 和 Canvas 紧凑区保留豁免。
- 顶级列表筛选工具带分为左右两组：左侧依次铺开名称/编码等主搜索框和所有当前可容纳的枚举条件；右侧固定放置“更多筛选、查询、重置”操作组。查询与重置必须贴近工具带最右侧，不能停在条件中间形成大片无意义空白。搜索框使用搜索图标和简洁占位文字。
- 普通输入框、枚举和时间范围只修改查询草稿，不直接请求；点击“查询”统一提交普通条件和已确认的高级条件，搜索框按 Enter 等同于点击查询。所有查询提交均回到第一页，不修改现有服务端查询协议。
- “查询”使用主按钮并固定在工具带右侧操作组。目录树属于导航上下文，选择后可立即刷新，但只能使用已经应用的查询条件，不得静默提交尚未查询的草稿。
- “更多筛选”是空间不足时的响应式降级，不是固定的信息层级。工具带能够单行容纳全部条件时，低频条件也应直接展示且不得出现“更多”；只有容器实际放不下时，才将低优先级条件折叠为“更多 · N”。折叠判断必须依据筛选容器的实际可用宽度，不得只按浏览器宽度或写死某个业务页面。弹层中的“确定”只保存草稿而不请求，“取消”丢弃本次修改，“清空高级条件”清除高级草稿，最终仍由工具带“查询”统一提交。
- “重置”在查询草稿、已应用条件、高级条件或目录任一非默认时展示；重置应清除普通、高级和目录条件并立即恢复默认列表。
- 结果工具栏左侧展示“资源列表名称”和“共 N 项”，右侧按“刷新、辅助操作、主业务操作”排列。刷新使用带 Tooltip 与 `aria-label` 的纯图标按钮，主业务操作使用主按钮，例如“+ 新建数据源”。不得另设重复的页面标题区。

### 表格与分页

- 管理页面的单行 Table 和 List 默认使用紧凑密度：表头高度 `40px`、数据行高度 `38px`、纵向内边距 `4px`，并统一使用 `size="small"`。Table 使用 `management-table`，List 使用 `management-list`，不得在普通页面重复声明相同行高。
- 名称/编码、名称/说明等双行身份信息，或包含 32～36px 资源图标时，使用共享 `ManagementListCell` 或 `management-table-comfortable` / `management-list-comfortable`，目标行高为 `52px`。只有健康状态、错误详情等确实需要多行内容的特殊表格才允许通过页面作用域覆盖为 `56～58px`。
- 紧凑密度规则只能作用于上述管理组件作用域，不得无边界覆盖所有 `.ant-table`、`.ant-list-item`，避免影响 Canvas、弹窗、Inspector 和其他专业工作区。
- 有分页的管理表格应始终在右下角显示分页，单页或数据较少时也不隐藏；默认显示总数和每页条数切换。无分页的静态或详情表格可例外。
- 翻页和修改每页条数应触发服务端查询；修改每页条数后应防止当前页码超出有效范围。
- 表头、分页保持可见，数据行在表体区域内部滚动。
- 单元格优先以“主信息 / 辅助信息”组合呈现：名称与编码、名称与说明、地址与目标、多个状态、日期与时间等相关信息应合并成一个语义单元，不得为每个字段持续增加独立列。
- 代码、URL、Topic、主机地址等使用纯文本等宽字体，不得渲染成带大面积灰底和边框的“禁用输入框”。可在点号、斜杠和连字符处换行，最多两行；被截断信息必须通过 Tooltip 可访问。
- 数值右对齐，空值统一显示为 `—`，日期时间使用项目统一格式。
- 主要列应指定合理宽度并按实际容器宽度分配；目录化列表不得将列宽预算按整个浏览器宽度计算。表格内容应优先压缩低频说明、合并语义字段和使用 Tooltip，而不是增加固定宽度。
- 以 1920×1080、浏览器 100% 缩放、主菜单和目录均展开为普通列表页的宽度验收目标。目录化列表的列宽预算不超过约 1360px，其他列表不超过约 1600px。不得用持续增大 `scroll.x` 处理字段过多问题，优先级依次为字段合并、两行展示、低频信息摘要与 Tooltip；目标分辨率下不得出现横向滚动。低于该宽度且确实无法容纳时，只允许表格内部横向滚动，不得造成页面横向滚动。

### 行操作

- 操作列保持窄且稳定。普通静止行优先只展示“更多”图标；行 Hover 或键盘 `focus-within` 时可展示最多 2 个高频纯图标操作和一个“更多”入口。触屏或无法 Hover 的环境必须仍能通过“更多”访问全部操作。
- 常用操作使用 `type="text"` 的纯图标按钮，每个按钮必须同时提供 Tooltip 和能够识别具体对象的 `aria-label`。名称链接已经承担查看或进入编辑器功能时不得重复展示查看按钮。
- 超出两个的操作、低频操作、辅助操作和危险操作统一收入“更多”菜单，不得通过持续加宽操作列容纳全部操作。操作出现与隐藏不得引发行内容或列宽抖动。
- 删除等危险操作使用 danger 语义并必须二次确认；确认内容应包含具体对象名称，避免误操作。

### 抽屉表单

- 普通资源的新建和修改优先使用 Drawer，保留列表上下文；仅在内容很少、需要强阻断确认或无法在抽屉中合理展示时使用 Modal 或独立页。
- 抽屉默认使用垂直表单；普通字段优先两列排列，强相关字段应分组，连接参数、高级选项等复杂内容使用明确分区。窄抽屉、长文本和复杂编辑器可使用单列。
- 抽屉底部操作固定右对齐，顺序统一为“辅助操作、取消、主操作”；保存、测试等异步操作必须展示 loading 并防止重复提交。

### 异步状态与反馈

- 列表加载使用表格 loading；行级命令只允许当前行的对应操作进入 loading，不得因一行操作锁定整列或整页。
- 新建、修改、删除、测试等命令完成后必须给出明确的成功或失败反馈；错误信息优先使用统一 API 错误转换结果。
- 无数据时使用统一 Empty 状态。列表加载失败时应给出持续可见的错误信息和重试入口，不得只显示一次性消息后留下空白页面。

### 目录树与列表

- 目录树和列表均占满可用高度并各自控制内部滚动，不得将滚动压力转移到整个页面。
- 展开状态的目录面板默认宽度为 244px，允许在 200～360px 且不超过可用内容宽度 35% 的范围内拖动调整；各目录页共享最近一次宽度偏好，双击分隔线恢复默认宽度。收起状态固定为 48px、禁止拖动，重新展开时恢复上次宽度。拖动不得造成页面级横向滚动。
- 目录内容区水平内边距约 8px，根节点不增加额外层级缩进，子层级每级缩进控制在 14～16px；展开开关与目录图标应保持紧凑，并让“全部”“未分类”和一级目录形成清晰的左侧对齐关系。目录图标与文字必须垂直居中，二者保留约 5px 间距，不得紧贴或依赖字体基线碰巧对齐。
- 目录行高控制在 36～40px，目录名称只能单行展示，超长名称使用省略号并通过 Tooltip 提供完整内容，不得换行抬高行高。资源数量使用固定宽度、低对比度数字块，不能挤占名称的主要空间。
- 目录树默认提供“全部”和“未分类”入口；选择目录后直接刷新右侧列表并回到第一页。
- 采用左侧目录树、右侧资源表格的页面，右侧表格不得重复展示“目录”或“所属目录”列；资源详情和编辑表单仍可展示目录信息。
- 从目录化列表新建资源时，选中具体目录应默认代入该目录且允许修改；选中“全部”或“未分类”时默认未分类。选择父目录时，即使右侧列表包含其子目录资源，新资源仍默认归入当前选中的父目录。编辑已有资源不得被当前目录选择覆盖。
- 目录树节点不得并排展示多个操作按钮。可管理节点固定预留一个窄的“更多”入口，在 Hover、选中或键盘聚焦时显示，触屏环境保持可见；菜单统一承载“新增子目录、修改目录、删除目录”。入口必须提供 Tooltip 与包含具体目录名称的 `aria-label`，危险操作必须保留具体名称和二次确认。
