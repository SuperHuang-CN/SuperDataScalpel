# MODEL_INPUT · 模型输入

[节点索引](index.md) · [Canvas 共用规则](../task-canvas.md)

## 用途与选择

批处理模型输入配置；按数组顺序全量读取一个或多个已发布纳管模型，每个模型产生一张 BOUNDED 逻辑表。节点不保存筛选条件、物理位置、连接或字段快照，运行准备时按当前模型生成权威快照。

## 模式与连线

- 模式：BATCH；类别：INPUT。
- 无入边，至少一条出边；不读取上游 Map。
- 输入有界性见下文。

## 关键配置与行为

- 每项只保存 modelId，数组内模型不重复；不保存源字段快照、物理位置或过滤条件。
- 按需读取模型详情和存储数据源，不能把 DRAFT 元数据当作已发布可读模型。实时静态输入应另选当前支持的 JDBC 节点。

配置定位（只列关键语义，完整字段读取实时契约）：

- `models`：按顺序读取的模型列表；至少一项，同一模型 UUID 不能重复。模型可以来自不同 JDBC 数据源，每项以模型不可修改的全局唯一 code 作为下游逻辑表名。

## 逻辑表 Map 与字段

产生以各模型稳定 code 为键的 BOUNDED 表，字段按模型元数据排序；不同模型 code 不能冲突。

## 最小配置示例

前提：UUID 指向已发布模型，模型 code=orders，已有物理表及字段元数据，所属 JDBC 数据源可用。

以下仅为节点 `configuration`；资源 UUID、字段与单位应换成已确认的真实元数据。稳定的操作/写入 ID 由当前任务生成。

```json
{
  "models": [
    {
      "modelId": "11111111-1111-4111-8111-111111111111"
    }
  ]
}
```

## 预校验检查与修正

将节点放入完整画布，按 Canvas 指南调用 Engine 预校验，核对输入/输出表及字段；此处没有真实数据测试步骤。

| 诊断或检查点 | 处理方式 |
| --- | --- |
| `MODEL_NOT_PUBLISHED` | 依赖用户准备已发布模型，不能自动发布。 |
| `MODEL_DATA_SOURCE_UNAVAILABLE` | 核对存储 UUID、数据源启用状态和快照。 |
| `DUPLICATE_TABLE_NAME` | 更换冲突模型选择或调整图，不能只改显示名称。 |

ERROR 修正后重新预校验最终定义；WARNING 记录影响，不把结构通过表述为数据值或输出结果通过。
