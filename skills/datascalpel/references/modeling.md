# 源数据分析与建模

## 范围与执行边界

支持从指定 JDBC 数据源，或指定数仓分层、目录、模型集合开始，结合业务场景分析元数据并设计目标模型。

**用户确认具体方案版本前，只调用只读能力并保存本地资料。确认后，只创建方案内必要的 `MODEL` 目录和包含完整字段的 `MANAGED` 模型草稿。** 不修改已有模型、不新建或更改分层、不建物理表、不发布、不创建或执行加工任务。用户修改方案时更新版本；影响设计的修改须确认后再执行受影响项。一次明确确认覆盖该版本中列明的创建操作，无须逐个资源重复询问。

## 1. 确定目标并建立工作目录

沿用对话已有信息，明确业务用途、来源范围、目标分层、存储数据源和目录位置。来源范围需能落到数据源及命名空间/表，或分层/目录/模型 UUID。仅澄清影响设计的歧义；未知的业务粒度、指标口径、关联条件不要自行补全成事实。

在 Agent 当前工作目录的 `modeling/` 下为本次任务创建独立目录，例如 `modeling/20260909-water-analysis-01/`。避免覆盖既有任务；建议结构如下，文件随实际进展生成：

```text
<本次任务>/
├── requirements.md          # 目标、范围、约束和用户补充
├── sources/                 # 来源与规划规则的元数据快照
├── analysis.md              # 覆盖范围、事实、推测、冲突及设计依据
├── proposal.md              # 当前待审阅方案；确认版本另存不可覆盖的副本
├── models/                  # 各目标模型的完整定义和来源映射
└── execution.json           # 方案、确认依据、计划对象、实际 UUID 与执行状态
```

快照按实际系统隔离，记录系统标识或连接地址（不含认证信息）、资源 UUID 或完整物理表标识（数据源 UUID、catalog、schema、table）、采集时间，以及可获取的 `updatedAt`、结构版本。需要本地结构摘要时注明它由哪些元数据计算，不能假称是服务端版本。**来源结构版本与 MCP 接口契约指纹分开保存**；契约指纹不能证明来源表未变化。

只保存分析必需的元数据、类型检查结果和结论。数据源响应需筛选后落盘，不保存令牌、连接凭据、连接选项或不必要的连接信息；不默认保存原始预览样本。缺少本地文件能力时说明无法满足资料保存与恢复要求，不声称已保存；可先解释方案，待具备能力后再执行依赖执行记录的创建。

## 2. 发现所需能力

按入口规则检索并读取最新契约。以下为当前接口定位指南，参数约束、枚举、必填项和响应结构始终以 `api_describe` 为准。不能依赖读取工程源码完成工作。

| 工作 | `operationId` |
| --- | --- |
| 查询、读取数据源 | `GET /api/v1/data-sources`；`GET /api/v1/data-sources/{id}` |
| 命名空间、物理表清单 | `GET /api/v1/data-sources/{id}/namespaces`；`GET /api/v1/data-sources/{id}/tables` |
| 表结构、少量样本 | `GET /api/v1/data-sources/{id}/table-metadata`；`GET /api/v1/data-sources/{id}/table-preview` |
| 查询、读取模型 | `GET /api/v1/models`；`GET /api/v1/models/{id}` |
| 按需预览已有模型数据 | `GET /api/v1/models/{id}/data-preview` |
| 分层及其规则 | `GET /api/v1/model-warehouse-layers` |
| 模型目录树、目录详情 | `GET /api/v1/directories`；`GET /api/v1/directories/{id}` |
| 常用字段模板 | `GET /api/v1/model-field-templates`；`GET /api/v1/model-field-templates/{id}` |
| 码表及适用说明 | `GET /api/v1/standard-dictionaries`；`GET /api/v1/standard-dictionaries/{id}` |
| 目标存储的平台类型能力 | `GET /api/v1/models/platform-types` |
| JDBC 源表到目标存储的受管导入预览（只读） | `POST /api/v1/models/managed-import-preview` |
| 确认后创建目录 | `POST /api/v1/directories` |
| 确认后原子创建模型及完整字段 | `POST /api/v1/models/managed-drafts` |

缺少必要查询、预览或创建能力时，列出未能获取的能力及其影响，保留已完成的分析。没有可见创建接口不等于系统不支持创建；没有冲突查询能力也不能当作目标不存在。不要用其他写接口代替缺少的只读检查。

## 3. 获取来源与规划规则

### JDBC 数据源起点

1. 确认来源数据源身份、JDBC 类型及启用状态；按命名空间读取所选物理表清单。保留完整 catalog/schema/table，不能只凭表名合并不同命名空间的表。
2. `/tables` 使用实际声明的 `catalog`、`schema`、`keyword`、`includeViews`、`limit`；当前最多 500 条，返回 `tables` 和 `truncated`。**它不是分页接口**，不能编造 `page` 或 `offset`。`truncated=true` 时缩小命名空间、关键词或用户范围，必要时说明只覆盖部分表，不声称全库分析完成。
3. 对纳入范围的表读取 `/table-metadata`，获取列、主键、索引、唯一键。当前返回不包含外键定义，不能凭同名字段断言关联关系。元数据不完整时记录缺口。
4. 仅在字段业务含义、值域等需要证据时少量预览；当前表预览 `limit` 默认 50、最多 100。样本不能证明全量唯一性、非空率或值域分布。敏感原值不复制到方案；预览不可用不妨碍已有结构分析。

### 已有模型起点

1. 分层筛选用 `warehouseLayerId`，例如 `search=warehouseLayerId:"实际 UUID"`；目录用 `directoryId`，模型集合用具体 UUID。按实际分页遍历用户选定范围。
2. 目录树查询使用 `scope=MODEL`，返回树而非分页结果。用户范围包含子目录时先解析后代目录，再按标量目录 ID 条件查询并去重，不能假定单个 `directoryId` 自动递归。
3. 模型列表只是概要，逐项读取 `/models/{id}` 中的 **`model` 和 `fields`**，保留模型及字段来源 UUID、结构、分层、目录、存储和状态。来源 UUID 仅用于追溯，不能成为新字段 ID。
4. 按需使用模型数据预览；草稿或物理表尚未建立可能无法预览，这不表示模型元数据不存在。

### 共同规划规则

- 读取现有分层的启用状态、`modelCodePrefix`、`inputLayerPolicy`、`allowedInputLayers`。按实际前缀设计编码；只规划业务所需模型，不机械铺满 ODS/DIM/DWD/DWS/ADS。
- 区分直接 JDBC 源表与输入模型分层。`ALLOW_LIST` 限制输入模型的分层，空列表表示没有允许的输入模型分层，不能据此禁止直接源表输入；`UNRESTRICTED` 与允许列表按真实规则解释。分层规则作为设计依据，不代表已经创建或校验了加工任务。
- 读取 `MODEL` 目录树、相关字段模板和适用码表。按用途复用，字段模板不意味着持久化模板关联；码表仅绑定兼容的现有码表，不在本场景新建码表。
- 目标存储必须是合适的已启用 JDBC 数据源，具有 `STORAGE` 用途。`purposes` 是集合，当前 Search DSL 不能对其做集合筛选；读取候选数据源后按响应筛选，不能把它当标量查询。
- 读取 `/models/platform-types`，指定 `storageDataSourceId`，核对平台类型及长度、精度、小数位、空间类型等能力，包含目标数据库要求的模型参数（如适用的 ClickHouse 排序列）。
- JDBC 起点使用 `/models/managed-import-preview`，传入 `sourceDataSourceId`、`sourceTable` 和 `targetStorageDataSourceId`，读取列映射、可导入性、问题与警告。`LOSSY`、`UNSUPPORTED` 必须显式报告并阻止受影响定义直接落地，不能静默改类型或删字段；需要调整来源或设计时纳入方案确认。
- 导入预览仅检查指定源表到目标存储的映射，**不是任意组合、派生或聚合方案的完整预校验**。已有模型和派生字段还需按目标类型契约核对。没有完整只读预校验接口时说明剩余服务端校验边界，禁止先建草稿来测试合法性。

## 4. 形成可确认的方案

先分析用户场景的数据粒度、事实与维度、业务主键、时间口径、关联条件和聚合规则。用证据支持字段与关系，将不确定内容标为推测或待确认；口径缺失影响设计时先澄清。可复用已有模型时说明复用方式，避免仅换名称复制。

在本地生成明确版本的方案及各模型完整定义，包含：

| 内容 | 审阅要求 |
| --- | --- |
| 总体设计 | 业务目标、模型用途与理由、数据粒度、输入来源、已有模型复用及模型依赖顺序 |
| 模型身份 | 名称、编码、分层、存储、物理表名及完整目录位置；区分已有 UUID 与待创建对象的本地标识 |
| 字段定义 | 全部字段的编码、名称、平台类型、适用的长度/精度/小数位/空间参数、可空、主键、顺序、说明及适用码表；不只列字段示例 |
| 字段口径 | 来源表/模型和字段、关联条件、转换、过滤、去重、聚合口径；区分直接复制与派生设计 |
| 目录计划 | 逐项列出拟复用与新建目录、父目录和范围；已有目录用 UUID 定位 |
| 覆盖与问题 | 实际分析范围、未覆盖表、事实与推测、类型冲突、名称冲突、待确认项及尚未完成的校验 |
| 执行清单 | 仅创建必要目录与完整 `MANAGED` 草稿，明确不包含物理建表、发布或加工 |

模型编码及目标物理位置需要检查与现有资源、方案内其他目标的冲突，按当前接口的编码规范化规则比较。目标物理表必须不存在，不能因为结构相同就复用已有表创建受管草稿。目标命名空间由存储连接决定，不能在请求里虚构 catalog/schema 来绕过冲突。截断表清单中没有目标名不足以证明不存在，应缩小到精确候选并检查元数据及错误性质。

展示方案摘要并提供可审阅的完整字段定义和本地文件位置，请用户确认明确版本。保存确认版本副本和用户实际确认的消息依据；不能把“帮我建模”的初始意图或本地 `approved=true` 当成对尚未展示方案的授权。用户要求修改时生成新版本，保留原确认记录，不能以旧确认执行改变后的设计。

## 5. 确认后执行

1. **复核条件。** 重新读取必要契约，检查来源结构、分层规则、目标存储状态、目录位置、模型编码及物理表冲突。契约更新且不影响设计时按最新格式提交；字段、口径、存储、位置或输入规则等变化影响已批准设计时，更新方案并重新确认受影响部分。无法核实必要条件则暂停相关创建。
2. **准备执行记录。** `execution.json` 关联系统、方案版本、确认依据和各计划对象的本地标识、类型、父对象、预期身份、实际 UUID、尝试时间、状态、HTTP/错误元信息。调用前标记正在尝试，调用后立即记录结果，不保存认证信息。请求 ID 仅用于追踪。
3. **按层级处理目录。** 以 `scope=MODEL`、真实父目录和名称定位；复用相同位置已有目录，创建方案内缺少的目录。不能只按叶子名称跨目录匹配。`POST /api/v1/directories` 请求只含当前契约支持的范围、父目录、名称、顺序和说明；父目录创建成功后立即保存 UUID，再创建子目录。发生冲突先重新读取，不能直接重发。
4. **准备请求并清理复制字段。** 新建字段必须省略 `id` 或置空，不能携带源模型、源字段或模板字段的 UUID；兼容的 `standardDictionaryId` 等业务引用按契约保留。类型限制、字段数量、编码规则以当前契约为准，不静默删除不合法字段。来源映射、关联、转换和聚合说明保存在本地设计中，不作为未声明属性塞入请求体，也不声称它们已经成为运行逻辑或系统血缘。
5. **逐个创建完整草稿。** 将批准的目标定义转换为当前 `POST /api/v1/models/managed-drafts` 请求，完成上述清理后，一次提交一个模型及全部字段。使用实际目录 UUID、分层 UUID、目标存储和物理表名。该接口自动创建 `MANAGED` 草稿，不额外传入物理表模式。
6. **保存与核对。** 每次成功创建后立即记录目录或 `model.id` 及服务端实际结果。模型和字段由该接口原子保存，不改用先建空模型再补字段的流程。读取目录和模型详情，核对编码、字段全集及类型、分层、目录、存储、物理表名、`DRAFT` 状态和 `MANAGED` 模式。服务端规范化造成偏差时如实记录；设计不符则停止相关后续项，不自行更新修补。

已创建资源的执行记录保存失败时，停止后续写操作，保留当前响应中的 UUID 并说明恢复所需信息，避免连续创建后丢失追踪。

## 6. 部分成功、不确定结果与恢复

- 业务明确拒绝时记录真实 HTTP 状态、稳定错误码及校验问题，不笼统说整个方案失败。修正仅限不改变批准设计的请求格式问题；需要改设计时重新确认。
- 写操作出现 `UNKNOWN`、`RESPONDED_INCOMPLETE` 或响应丢失时，标记待核实。优先按已知 UUID 读取；没有 UUID 时按模型编码或目录的 `MODEL + parentId + name` 定位，结合字段、位置和其他可用证据核对，不能直接重发创建。
- 同名资源不自动证明本次创建成功。无法确定身份、状态或归属时暂停受影响项，报告已有证据和需核实内容；查不到也可能是权限、可见范围或请求仍在处理，不能立即推断可以重试。
- 中断后先读取方案、确认依据和执行记录，并查询系统现状。继续使用已成功资源的 UUID，逐项核对后推进仍获授权的剩余项；本地状态不能代替实际查询或用户授权。
- 保留部分成功资源，不自动删除回滚、不覆盖同名对象。依赖未确定目录或模型的后续项暂停；仅在边界明确时继续已授权的独立项。失败项、未执行项和待核实项分开报告。

## 7. 交付

交付实际创建或复用的目录、模型名称/编码/UUID、核对结果和未完成项，附本地需求、确认方案、目标定义和执行记录位置。仅在已知前端基地址及真实路由时提供页面入口，不从 MCP 地址猜测页面 URL。

说明产物是模型草稿，物理表、数据装载、关联加工和任务尚未创建；本地来源映射用于后续设计衔接。只分析或部分成功时明确实际完成范围，不把规划文档称为已落地模型。
