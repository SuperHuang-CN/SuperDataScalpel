# 批处理任务

与一种开发方式配合读取：[Canvas](task-canvas.md) 或 [在线 JAR](task-jar.md)。本指南用于确定批次和写入语义，不要求运行任务验证结果。

## 先确定批次边界

沿用用户已提供的来源、目标和业务口径，仅澄清影响设计的歧义。形成以下设计事实：

| 设计项 | 必须明确的内容 |
| --- | --- |
| 输入范围 | 模型或数据源资源 UUID、物理表位置、所需字段、全量快照还是时间/主键范围；模型列表不能代替详情中的字段 |
| 批次边界 | 起止值、包含/排除关系、时区、迟到与补数规则；增量游标由谁保存和推进，不能假设平台自动维护 |
| 结果粒度 | 一行代表什么、关联基数、聚合分组、去重依据和稳定排序；缺少证据的关联关系单独说明 |
| 输出依赖 | 已存在的目标模型/物理表/文件存储、字段类型、可空性、默认值、生成列、主键与唯一键 |
| 重复提交 | 同一批次再次运行可能追加重复数据、覆盖结果或更新同键数据；失败后部分写入的处理责任 |

批处理使用有界输入。`MODEL_INPUT` 读取已发布模型的当前全量快照，没有内置增量过滤。需要限定批次时使用适用的过滤、受控 JDBC 查询或 JAR 参数设计；不能把仅支持实时的 `JDBC_INCREMENTAL_INPUT` 塞入批画布。

## 选择输出语义

- `APPEND`：保留目标原记录并追加；不能声称重复运行天然幂等。
- `OVERWRITE`：按目标实现的覆盖语义设计，明确受影响范围；不是默认按业务主键更新，也不等于自动物理建表。
- `UPSERT`：明确业务键和目标约束；模型使用完整模型主键，JDBC 使用明确的更新键。映射中的目标键必须有来源，不能从字段名称猜唯一性。
- 完整快照对齐：只有需要“小规模完整源快照与目标对齐”时选用对应快照同步输出。`KEEP` 保留源中消失的目标行；`DELETE` 涉及真实删除，需在方案中列出删除阈值和空源保护。局部增量不能当作完整快照使用。
- 文件输出：明确目标相对路径、格式和冲突策略。这里只设计运行时输出，不通过 MCP 上传下载文件，也不为验证创建输出文件。

读取当前目标平台能力，遇到不支持的类型、键或写入方式先报告依赖/限制。缺少模型、物理表、连接或权限时，不自动建模、发布模型、建表或更改基础设施。

## 交付判定

Canvas 创建类型为 `SPARK_CANVAS`，编译模式显式为 `BATCH`；在线 JAR 创建类型为 `SPARK_JAR`，使用批处理入口。任务类型创建后不能切换。

按所选开发方式完成确认和保存，交付 `DRAFT`。Canvas 报告“Engine 预校验通过，未运行”；JAR 报告“在线编译成功，未运行”。业务口径、批次重放和输出效果列为用户后续验收事项，不调用试运行、样本预览、正式运行、调度或发布接口。
