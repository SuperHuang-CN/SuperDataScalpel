# 网关运维统计页面

## 1. 页面目标

网关运维统计页面帮助运维人员按时间、数据服务和 API Consumer 查看调用规模、成功率、错误
归因和延迟变化，并从异常明细继续定位单次网关请求。

页面位于 DataScalpel 单体前端的 `dataservice` 业务域，路由为
`/dataservice/operations`，沿用 `service.view` 权限。页面只读取访问日志和小时统计，不执行
告警、限流、配额扣减、计费或网关配置变更。

## 2. 时间与刷新语义

- 24 小时视图按小时展示；
- 7 天视图将小时结果合并为每 6 小时；
- 30 天视图将小时结果合并为每 24 小时；
- KPI、趋势和排行只查询 UTC 已完成小时；
- 页面展示用户本地时间和 UTC 偏移，HTTP 参数仍使用 ISO UTC；
- 页面每 5 分钟自动刷新一次，标签页在后台时暂停，并提供手动刷新；
- 最近十五分钟实时卡片每 15 秒刷新，直接聚合已入库原始日志，包含当前小时；同时显示日志接收开关及最近调用时间，不把“开启接收”当作 Kafka 正常投递证明。
- 原始明细默认显示全部调用，可切换“仅异常”，可以包含当前未结束小时，且无论统计范围如何都最多查询最近 7 天。

页面合并趋势桶时，请求数和状态数求和，错误率使用合并后的计数重新计算。P95/P99 使用桶内
小时分组最大值。概览中的 P95/P99同样表示查询窗口内的小时峰值，不代表把多个小时的原始
延迟样本重新计算后的整体分位数。

## 3. 页面结构

顶部筛选包括时间范围、数据服务、API Consumer、重置和刷新。服务和 Consumer 使用现有分页
Search API 按关键词远程查询，不预加载全部主体。

页面主体依次展示：

1. 调用总量与窗口平均 QPS、2xx 成功率、小时峰值 P95/P99、5xx 错误率；
2. 调用量、错误率、延迟三种趋势，以及 2xx/4xx/5xx 响应构成；
3. 401、403、429、网关错误和上游错误；
4. 服务排行和 Consumer 排行，点击主体后联动全页筛选；
5. 最近调用分页列表（全部 / 仅异常）。

Request ID 可打开调用详情抽屉。抽屉只展示规范化白名单字段，包括请求路径、状态、Provider、
身份解析状态、延迟、流量、客户端 IP、网关外部 ID 和 Kafka 坐标；不会展示 Header、Body、
查询参数、API Key、Authorization 或 Cookie。

## 4. 异常责任边界

明细责任边界按以下优先级表达：

1. 401：调用认证；
2. 403：授权 / IP 策略（也可能是消费者停用或订阅未到生效时间/已到期，不能只解释为未订阅）；
3. 429：网关限流；
4. `upstreamError=true`：上游服务；
5. `gatewayError=true`：网关错误；
6. `gatewayRejected=true`：网关拒绝；
7. 其他 5xx：服务端未分类；
8. 其他 4xx：调用方。

各区域独立展示加载和错误状态。概览、趋势、排行或明细中的单个请求失败，不清空其他已经成功
加载的区域。

413 表示请求体过大，499 表示客户端中断；2xx/3xx 分别显示成功/重定向。
`GET /api/v1/gateway-access-statistics/recent` 按可选 dataServiceId / consumerId 过滤最近十五分钟，返回调用/成功/4xx/5xx/拒绝、平均与 P95/P99 延迟（ms）、最近请求/入库时间；没有延迟样本时返回 null。实时统计不是小时汇总的增量，不与小时结果相加。
