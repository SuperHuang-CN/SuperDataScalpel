# WGS84 非点最近位置：内部实现与接入边界

状态：2026-09-12 共享算法开发。Reconstruct 局部测地面及非点 gap 已在 4.44 接入，
详见[重建第 17 节](canvas-spatial-next-processors/track-reconstruct.md#17-canvas-444-局部测地面轨迹节点接入)。
Nearest 的非点真实测地已通过 Canvas 4.48 的显式 `GEOMETRY` 模式开放；旧 4.30 定义缺失该字段时仍按
`POINT_ONLY` 解释，不静默改变旧任务。Manifest、Result、HTTP API 和生产依赖未改变。
下文保留早期算法的语义边界；旧阶段所述“未接入”不覆盖后续重建节点进展。

## 1. 为什么不能继续使用质心

- 当前 Sedona 1.9.0 的 `Spheroid.distance` 对非 Point 使用 `getCentroid()`，不是 Geometry 间最近距离。
  Nearest 的 `EXACT_DISTANCE + GEOMETRY` 使用本文的真实位置/距离路径；旧 `POINT_ONLY` 与 `LEGACY_KNN`
  分别保留仅 Point 和既有质心兼容结果，不悄悄改变旧任务。
- Enterprise 11.3 Reconstruct Tracks 文档把 distance split 描述为相邻输入要素相距超过阈值，
  所列说明未明确多边形质心规则，不能把质心策略当成已经验收的官方语义。
- 点到面内部、相交面之间的 Geometry 距离应考虑区域关系，不能只扫描外环/孔洞边后返回正距离。
  线性入口继续明确拒绝 Polygon；新增区域入口先判断实际区域关系，再求必要的边界最近距离。

冻结参考：

- [Enterprise 11.3 Reconstruct Tracks](https://enterprise.arcgis.com/en/portal/11.3/use/geoanalytics-reconstruct-tracks.htm)
- [Reconstruct Tracks REST](https://developers.arcgis.com/rest/services-reference/enterprise/geoanalytics/tasks/reconstruct-tracks/)
- [Enterprise 11.3 Find Nearest](https://enterprise.arcgis.com/en/portal/11.3/use/find-nearest.htm)：标准要素分析，不是 GA Server 工具。

## 2. 线段级搜索

`Wgs84SegmentDistance` 使用现有 GeographicLib 的 WGS84 正/逆解，支持有限最短测地线段间最近距离，
退化线段即 Point。位置使用不可变经纬度 record，不传 Spark、JPA 或稳定配置对象。

- 沿第一条线段的弧长为 s，第二条为 t，搜索整个 `[0,L1] × [0,L2]`。
  不只找端点、不取质心、不采用经纬度直线或投影最近位置作为最终结果。
- 端点对和每个搜索区间中心给出实际可达到的距离上界与两侧最近位置候选。
- 测地距离在两个弧长方向分别满足 1-Lipschitz：改变 s 或 t 的距离变化不超过对应弧长。
  因而区间下界为 `max(0, 中心距离 - s半宽 - t半宽 - 舍入裕量)`；子区间继续继承父区间下界。
  初始区间还使用对角端点的三角不等式下界。
- 优先细分下界最小的区间，沿弧长较长的一侧二分。区间始终覆盖完整参数域，
  不假定函数单峰，也不依赖单次局部优化就判定已找到全局最近位置。
- 两侧原始边各建立平衡 ECEF 包围盒树。树对与已展开的弧长区间进入同一个全局优先队列，
  共享当前最小上界与预算；不再先物化全部边对，也不把每个远处边对独立算到精度才比较下一对。
  只有队首树对仍可能影响答案时才展开；叶对才创建原有完整弧长搜索。
  高重叠/长边的最坏情况仍可能退化为二次边对，不能以分层索引宣称任意规模已解决。
- 增加 ECEF 弦下界：在若干单位轴上求两条端点弦投影区间的分离量，再扣除每条测地弧的
  `弧长² / (8 × WGS84 最小主曲率半径)` 偏离裕量。任何轴的分离量都不会大于真实弦间距离；
  没有找到最优轴只会少剪枝，不会排除真正最近位置。
  弦仅用于保守下界，不替代最终测地距离；与原有 Lipschitz 下界取较大者。
- 当 `最小已采样距离 + 舍入裕量 - 所有区间最小下界 <= 请求精度` 时返回。
  返回同时包含两侧位置、实际位置对距离与全局下界，不能只取一个 double 隐藏未决误差。
- ±180° 及极点等价经度规范化。线段端点按固定顺序选取 GeographicLib 最短分支，
  反转同一线段不改变分支或采样平局。对跖点多解仍是平台分支选择，不宣称官方选择一致；
  接入已有路径/面环前须统一分支语义，不能让同一几何在两个算法中走不同路线。

## 3. 数值与计算量边界

- 内部精度参数单位为米；当前要求有限且至少为四倍 `1e-6 m` 舍入裕量。
  该裕量为双精度正/逆解的工程保护，不是严格区间算术证明，也不是 ArcGIS 默认精度。
  测试中的 0.001/0.01/0.1 米不是新节点的产品默认值。
- 距离误差界不等于最近位置的坐标误差界：近似等距区域可以存在相距较远的近最优位置。
  连接线必须使用同一次搜索返回的位置对，不能另行计算质心连接或混用另一轮结果。
- 不将“距离小于精度”自动改成零，不以此代替 Polygon 内含、相交或接触拓扑。
  内部阈值判定已按下述区间规则继续求精；Nearest 4.48 已接入半径和区间排名，TrackArea gap 等其他
  调用点仍需分别贯通。任何入口都不得直接将上界当成无误差真值。
- 单次几何搜索共享最多 250,000 个 Budget 工作单位；距离/位置取样、树叶准备、内部节点构造及树对展开
  均消耗同一个 Budget，不按每条边或每次区域定位重置。该单位不是 CPU 指令数，排序比较不逐次计数。
  极点到赤道弧、很长的近似平行线等近乎等距情形可能需要大量细分，超限明确失败，
  不返回上限前的未验证候选。优先队列内存也受该取样次数限制。
- 到达浮点弧长不可再细分的分辨率且仍不满足精度时失败。算法没有 Action、缓存或外部 I/O。
  它不是完整大数据候选索引；不能将几何内边对循环当成跨表空间关联的执行方案。

## 4. Point 与线性 Geometry 入口

`Wgs84LinearDistance` 接收原始 EPSG:4326 XY Point/MultiPoint/LineString/MultiLineString：

- 先检查两侧全部实际坐标、维度和类型，再搜索所有真实边对。无效的后续坐标不能因前面相交而被跳过。
- Point 作为退化边；多部件之间不补连接线，开放折线不补闭合边。自交折线按其实际轨迹处理。
- 所有边对共享一个 Budget 和优先队列；整体距离上界取最小位置对，下界取全局队列最小下界。
  已有上界在精度内接近零时可利用距离非负这一全局下界提前完成，不伪造尚未检查的正距离结果。
- NULL/Empty 返回 NULL，空部件不变成原点。输入 Geometry 不修改；源顶点最多一百万。
- 该窄入口仍不接受 Polygon/MultiPolygon 或 GeometryCollection；面区域使用下述区域入口。
  Canvas 4.48 的 Nearest 统一通过组合入口调用两者，并继续明确拒绝 GeometryCollection。

### 局部 Polygon/MultiPolygon 区域入口

`Wgs84PolygonRegion` 与 `Wgs84GeometryDistance` 增加实际面区域关系：

- 使用 `TrackGeodesicPolygon.prepareSource` 检查原始域/环/区域，**不再创建或校验采样渲染面来准备测距**。
  定位使用原始 WGS84 测地环从查询点观察的方位绕数，外环内且所有孔洞外才是面内部；多部件取并集。
  点在孔洞中的距离为到孔洞边的正距离，而不是零。
  内部 `Wgs84PolygonRegion.prepare(shape)` 和 `Wgs84GeometryDistance.nearest(first, second, toleranceMetres)`
  已移除渲染步长参数；距离精度和输出边界的采样粒度是不同职责。
- 当前验证域仍是局部强凸球：顶点距明确参考小于 `π × WGS84 半短轴 / 2`。
  查询点在该球外不能属于其内的 minor region，先判 OUTSIDE，避免反向点的方位绕数误选球面补集。
  半球/全球域并未因此完成，也不作为最终目标的范围缩减。
- 同一强凸域内，各最短边对查询点的方位扫角取小于 180° 的分支；有符号绕数采用补偿求和。
  内含不取 Geometry 质心，不补日期线辅助边或多部件之间的虚拟连线。南北极任意经度视为相同物理点。
- 精确命中任一原始环顶点优先确认 BOUNDARY，包括孔洞顶点接触外环边内部的情况；
  原始顶点采用物理位置规范化集合，不让外环先遇到的未决扫角遮蔽明确边界证据。
  接近 180° 的对向方位返回 UNRESOLVED，
  不按角度阈值吸附成边界，也不猜测点在面内还是面外。
- 两侧完整校验后检查所有独立原顶点（含开放线的最后端点）。任一顶点属于另一面闭区域时，
  用该真实公共位置返回距离零和同一位置对，不再错误地返回相隔很远的边界距离。
- 无内含顶点时，对所有原始边做全局搜索。交叉面可以没有任何内含顶点，此时边界距离区间包含零。
  数值上界仍由实际位置对取得，不自动变成零；未决定位只有在边界上界满足请求精度时才返回 `[0, 上界]`，
  否则返回精度未达错误，不把未知内含关系丢弃后返回正下界。
- 点/多点/线/多线与 Polygon/MultiPolygon 可在该内部入口组合；通用 GeometryCollection 尚未开放。
  来源 Geometry 不修改，NULL/Empty 保留。区域定位与边界取样共享同一个预算。

### 原始连续弧检查与接触点节点化

- `Wgs84ArcTopology` 在已验证的共同局部强凸域内判断有限测地弧关系，返回
  DISJOINT / CROSS / TOUCH / OVERLAP / UNRESOLVED。方位侧向符号有 `1e-12` 正弦保护区，
  近共线非轴向位置不视为精确共线；只有边界距离的正下界能证明分离时才从未决转为 DISJOINT。
- 原始公共端点、赤道及经线上的有限弧接触/重叠使用明确结构判断，包含日期线与极点等价位置；
  不将支撑线上的远处点误判在有限弧内。失败的域检查不进入已验证位置缓存。
- `Wgs84PolygonArcCheck` 在采样前遍历可能相遇的原始边：交叉、重叠、同环非相邻接触拒绝；
  相邻端点和不同环的单点接触不自动当作交叉。未决返回 `GEODESIC_TOPOLOGY_PRECISION_NOT_REACHED`，
  不依赖渲染采样长度决定连续交叉是否存在。
- 使用既有 STRtree 索引保守 ECEF 包围盒，始端点各坐标加减整条测地弧长覆盖完整弧；
  后续改为弦端点范围加曲率裕量，见下节；索引两个最大跨度轴，候选再检查三轴。
  这只剪枝，不用 ECEF 线段相交代替 WGS84 谓词。
  建盒、每次候选访问、域校验、方位/距离回退、接触排序取样及后续区域关系检查共享单次拓扑检查的 250,000 次预算。
  该拓扑准备预算目前与后续距离搜索预算分开，不声称整个复合操作只有一次预算。
- 已确认的 T 接触点按弧长顺序加入相应边，返回独立不可变环再采样。只插入真实接触点，
  不移动原坐标、不吸附近邻、不修改来源 Geometry；重复处理不再次增加顶点。
  这修复了真实孔洞顶点落在采样外环弦外侧而被错误拒绝的问题，未放宽孔洞切断面内部的限制。

### 原始区域关系与内部连通

`Wgs84PolygonTopology` 在简单环及明确接触点已验证后处理区域约束，不调用 JTS 平面有效性检查：

- 不相交的两个简单环，由一个可可靠定位的原始顶点确定包含关系；近对向方位未决时改查其他顶点，
  全部未决则安全失败，不将它当作区域外部。
- 有公共接触点时，逐段检查相邻接触点之间的开放弧。取接触后的首条原始边内部位置，用另一原始环定位；
  定位未决时尝试该边其他内部位置，仍未决则失败。不同开放弧位于两侧说明在公共顶点穿越，必须拒绝。
  这不是靠增加渲染分段数寻找交叉；已验证的连续边关系保证一段无其他接触的开放弧不改变区域归属。
- 每个孔洞必须在所属外环内，同一 Polygon 的孔洞不能相互包含。MultiPolygon 的一个部件可以是另一部件
  孔洞中的岛，但不得在另一部件的填充区域内；部件排序、环方向不改变该关系。
- 每个 Polygon 构造“环—接触位置”二部图并检查环路。三条环在同一点相遇形成星形，不误当环路；
  真正闭合的孔洞接触链或外环—孔洞—外环链会切断区域内部，必须拒绝。不同 Polygon 的内部无需彼此连通。
- 环对定位结果只在单次校验中缓存，环关系和接触图继续消耗同一次拓扑预算。来源 Geometry 不变，
  `Source` 只持有局部参考和不可变原始/节点化环，不携带渲染 Geometry。

### 区域检查的证据边界

原始局部区域有效性已与等距方位图及经纬度渲染布尔结果分离；原来的采样平面拓扑校验路径已删除。
面轨迹的偏移带、圆形连接、日期线切分和 Union/Difference 输出仍是离散表示，渲染失败不再使测距准备失败。
该局部域与浮点方位保护仍不是任意全球拓扑或严格区间算术保证，非轴向极近共线仍可明确失败。
已验证局部域内的 CROSS 使用 GeographicLib Gnomonic 迭代求公共位置，并以两条有限 WGS84 弧的投影残差复核；
只有复核通过才向最近位置结果返回同一位置对和确定零距离。求解不稳时仍保留 Boolean 相交事实并返回未决区间，
不编造连接线端点；这也不构成任意全球域或官方数值等价证据。

### 距离阈值的区间判定

内部 `Wgs84GeometryDistance.withinDistance(first, second, thresholdMetres)` 判断包含边界的 `distance <= threshold`：

- 阈值必须有限且非负。两侧完整类型、坐标和原始区域验证先于任何“范围内”短路；NULL/Empty 继续返回 NULL。
- 已有真实内含/共同原始位置时，零距离可以直接证明范围内。低于舍入裕量的阈值另外使用下述
  连续边界拓扑事实，不将数值上接近零的边内位置对吸附为共同位置。
- 阈值查询与最近距离查询复用同一个完整边对优先队列及细分实现，只改变停止条件：
  `已取得位置对距离 + 舍入裕量 <= 阈值` 才判范围内；`全部未排除位置的全局下界 > 阈值` 才判范围外。
  区间跨过阈值时继续原队列，不用固定粗精度结果比较，也不逐轮重新构造搜索或重置预算。
- 任一真实边界位置对可证明足够接近；但存在未决区域包含关系时，正边界距离不能证明面区域分离。
  此时若边界搜索判范围外，整体返回精度未达错误，而非把未决包含丢弃。
- 当前双精度保护区内的相等/极近阈值可以返回 `GEODESIC_DISTANCE_PRECISION_NOT_REACHED`；
  预算耗尽则返回工作量错误，不返回猜测 Boolean。无法验证局部域或近共线关系的零阈值查询仍可能失败。
  这是显式未决语义，不是用隐藏 epsilon 改变阈值，也不是已实现任意零距离拓扑查询。
- TrackNodeSupport 仍有自身调用边界；NearestExactPlan 已通过单次匹配 Struct 使用同一上下界规则。
  4.48 新增显式 Geometry 模式，旧任务不变。

### 零阈值的连续边界证据

- `Wgs84BoundaryIntersection` 返回 INTERSECTING / DISJOINT / UNRESOLVED，三种状态不能合并。
  先检查规范化的原始共同端点，再以保守 ECEF 弧包围盒索引候选；被盒分离排除的边对已确定不相交。
- 每个剩余边对用 `Wgs84ArcTopology.probeLocal` 检查连续关系。四端点单位向量均值只提出参考，
  随后仍以 WGS84 逐点验证共同局部域；参考不作为质心距离或交点。平均向量退化或域不成立时返回未决，
  不把缺少局部证明当成两条全球弧已分离。
- CROSS、TOUCH、OVERLAP 均可证明边界非空交集；所有候选均已分离才返回 DISJOINT；
  没有相交证据且至少一对未决则返回 UNRESOLVED。轻量探测不为每个未决边对立即启动完整距离搜索，
  后续候选仍可提供相交事实，不让一个近共线候选提前耗尽预算。
- 阈值小于 `1e-6 m` 时使用上述事实：相交直接判范围内；零阈值且边界已分离直接判范围外。
  正但极小的阈值不能只凭不相交就判范围外，仍需原数值区间搜索。未决同样回到共享预算的数值搜索，
  不新开预算。区域包含未决时，外围入口仍禁止将边界分离当成整个面区域分离。
- `Wgs84BoundaryIntersection.Match` 除三态关系外可携带经过验证的公共位置：共同端点、可确定接触/重叠
  以及局部 CROSS 交点进入 `Result`；只有 Boolean 证据而无稳定位置时 contact 保持 NULL，绝不填入推测坐标。
- 已覆盖高纬真实弧、日期线、极点、有限接触/重叠、无内含顶点的交叉面和两组各 1024 条分离边。
  这不是任意全球拓扑的完成证明；大域和非轴向极近共线仍可能安全失败。

### 完整边对域的分层距离搜索（4.47）

- `arcBox` 使用弦端点各轴范围加 `L² / (8 × WGS84 最小主曲率半径)` 与舍入裕量覆盖整条真实测地弧。
  该界来自单位弧长参数的加速度上界，不依赖采样密度。日期线、高纬弧顶点及所选对跖分支都在包围盒内。
  同一保守盒也用于原有拓扑候选索引；只收紧候选，不改变连续谓词。
- 内部树节点为子盒的并集，两树盒的 ECEF 分离距离不大于其任一真实点对的弦距，更不大于测地距。
  展开树对/弧长区间时继承父下界，未访问的边对始终保留在队列所代表的完整域中。
- 任一真实端点对仅提供初始上界，不决定保留哪些候选。队列按下界排序，同下界按插入次序处理；
  最终仍用原有“达到请求距离误差”或“严格落在阈值一侧”停止条件，不用近似质心排名或隐藏半径。
- 单边对保持直接路径；多边对在首次短路前仍完整检查两侧坐标，建树与细化共享预算。
  返回的两侧位置与距离来自同一次实际取样，不将毫米级距离区间解释成精确交点/端点。
- 分层搜索作用于一对 Geometry 内部，不是跨表最近邻索引。本阶段尚未单独解决全表召回、区间排名、
  公共交叉坐标或全球面域；后续 4.47/4.48 增量分别补齐前三项的安全接入，全球面域仍未开放。
- 专项覆盖两侧各 2049 条原始边（约 420 万组合），在 20,000 工作预算内找到最后一组的边内最近位置，
  并判断 10/12 米阈值两侧；小集合与全部单边对求解对照，检查排列、交换、全球弧包围、非法末项及预算。
  最终专项与 Executor 回归结果以[进度记录](canvas-spatial-development-progress.md)为准。

### 跨表候选的 ECEF 保守召回基础（4.47）

- 每条 WGS84 Geometry 可生成 `ECEF X/Y 包围 Geometry + Z 区间`。线性部分复用连续弧的弦端点/曲率裕量盒；
  Polygon/MultiPolygon 先走原始区域校验，再把六个椭球笛卡尔轴极值中位于区域内或数值未决者纳入。
  因为每个笛卡尔坐标在椭球面内部的驻点只可能是相应正/负轴点，边界弧盒与这些点共同覆盖完整填充区域，
  包括孔洞和多部件；包围盒只允许多召回，不能漏掉真实 Geometry 点。
- 4.47 的 Point EXACT_DISTANCE 测地候选先改用此路径。配置半径 R 时，先以 ECEF XY 包围距离不大于 R 且
  Z 区间差不大于 R 召回；因为 ECEF 弦距不大于 WGS84 面距离，真实距离不大于 R 的候选不会被排除。
  最终半径筛选和排名使用下述同一 WGS84 匹配 Struct，不把 ECEF 平面距离写入结果。
- 无业务半径时，ECEF XY KNN 只负责取得任意已验证候选的真实 WGS84 距离上界，再用上述三轴条件恢复
  上界内全部候选；二维种子可以选错，但不能决定最终候选集合。极区反例显式验证 XY 完全重合的远端种子
  不会遮蔽 Z 相近、真实更近的候选；有/无业务半径均恢复正确结果，执行计划没有退化为笛卡尔积。
- 包围构造、候选 Join 和 Analyzer 均不触发额外 Action；实际 UDF 在 Executor 消费时验证数据。
  这一步建立了非点跨表召回所需的保守索引；4.48 的显式 Geometry 模式复用同一路径。

### 距离、区间与最近位置的单次匹配 Struct（4.47）

- `Wgs84NearestMatch` 在一次 Geometry 对求解中返回实际取样距离、真实最小距离的下/上界、两侧最近位置组成的
  二点 LineString、`provenZero` 和 `exactDistance`。单个 Point–Point 及具有同一真实位置的零距离可标记为
  确定数值；4.48 后续将 Point/MultiPoint 双方均为有限点集的组合也改为离散精确分支，只有全局 ECEF 树中
  所有可能更优或同距的点对都已访问/排除才标记确定。线/面搜索仍保留有限区间，不能把小区间改写成确定距离或交点。
- 4.47 的 Point EXACT_DISTANCE 先消费该 Struct：无半径种子的 WGS84 上界、召回后最终距离、半径判定和连接线端点来自
  同一类求解结果。连接线 UDF 只对 Struct 中的两端位置加密并切分日期线，不再从原 Geometry 独立求最近位置。
  主结果表与连接线表仍共享一份惰性匹配关系；Spark 多个下游 Action 可能重算计划，不等于缓存或物化一次。
- 半径边界只在 `upper <= radius` 时保留、`lower > radius` 时排除；区间跨越半径时返回
  `GEODESIC_DISTANCE_PRECISION_NOT_REACHED`，不按近似值猜测。Top N 按取样距离形成候选前缀后，每个入选项都与
  全部后续非确定候选的最小下界比较；入选项自身非确定时还需覆盖后续确定候选。确定 Point 距离可按候选 ID
  处理相等距离，非确定区间只有严格分离时可排序，重叠同样安全失败。
- 4.48 的非点模式沿用同一 Struct 和区间门槛。局部 CROSS 若取得经过验证的公共位置则是确定零距离；
  Point/MultiPoint 的有限离散最小值可直接参与稳定同距排序；其他线/面结果保留区间。半径或 Top N 无法由
  区间证明时安全失败，不按取样值或候选 ID 猜测。

### Canvas 4.48 显式非点 Nearest 接入

- `SpatialNearestMatching.geodesicGeometryMode` 新增 `POINT_ONLY | GEOMETRY`。缺失/null 使用 `POINT_ONLY`；
  显式 `GEOMETRY`（即使在 LEGACY_KNN 非活动草稿中）要求 4.48。新建节点默认 `GEOMETRY`。
- `GEOMETRY` 支持 EPSG:4326 XY Point/MultiPoint/LineString/MultiLineString/Polygon/MultiPolygon；已知
  GeometryCollection 编译拒绝，通用 GEOMETRY 在 Executor 按实际类型检查。双方即使同为 XYZ/XYM/XYZM
  也不能进入测地路径。
- ECEF 三轴只召回候选；最终半径、Top N、距离和连接线都使用一次 WGS84 Match。Point→Line、线线高纬/日期线
  交叉、点在面内、点在孔洞内、无内含原顶点的面面交叉以及 Multi* 都走真实 Geometry，不使用质心。
- Polygon 的每个连通部件仍受局部强凸域约束；MultiPolygon 若无法放入同一域，会逐部件复用一个总工作预算验证。
  只有每个部件独立合法，且跨域部件之间的边界分离与双向非包含均可证明时才接受。因此相距全球不同位置的
  小部件不再被共同参考点误拒绝；跨域接触、相交、包含或数值未决仍安全失败，不使用经纬平面关系补判。
- 单个跨域 Polygon、跨域连通/接触 MultiPolygon、数值精度和工作预算边界尚未开放；无法证明时返回稳定
  安全错误，不回退 Sedona 质心。该边界在 Inspector 就近说明。
- Point/MultiPoint 双方均为有限点集时，分层队列处理完所有下界可能优于或等于当前最优的点对后返回精确最小值；
  同距按真实距离和候选 ID 稳定处理。树构建、点对求值仍共享 25 万次保护，不枚举无界笛卡尔积；线/面近等距
  仍使用上下界并在无法证明顺序时失败。

## 5. 安全错误

所有错误消息不含坐标、距离值或数据内容；底层没有被转存为带坐标的异常 cause。
Runner 在通用空间库异常之前识别以下代码，均不可重试：

| 错误码 | 类别 | 含义 |
| --- | --- | --- |
| GEODESIC_DISTANCE_COORDINATE_INVALID | SCHEMA | 非法经纬度、CRS 或实际维度 |
| GEODESIC_DISTANCE_GEOMETRY_UNSUPPORTED | SCHEMA | 当前入口尚不支持的几何类型 |
| GEODESIC_DISTANCE_GEOMETRY_INVALID | SCHEMA | 面区域、环、孔洞或部件关系无效 |
| GEODESIC_DISTANCE_REGION_RANGE_NOT_SUPPORTED | SCHEMA | 超出当前局部区域验证域 |
| GEODESIC_DISTANCE_WORK_LIMIT_EXCEEDED | SCHEMA | 实际搜索/输入超过计算量保护 |
| GEODESIC_DISTANCE_PRECISION_NOT_REACHED | SCHEMA | 达到数值分辨率边界仍未满足精度 |
| GEODESIC_TOPOLOGY_PRECISION_NOT_REACHED | SCHEMA | 连续弧近接触关系无法可靠判定，未吸附或猜测 |
| INVALID_GEODESIC_DISTANCE_PRECISION | CONFIGURATION | 内部精度参数非法 |
| INVALID_GEODESIC_DISTANCE_WORK_LIMIT | CONFIGURATION | 内部预算参数非法 |
| INVALID_GEODESIC_DISTANCE_THRESHOLD | CONFIGURATION | 内部阈值不是有限非负数 |

当前没有将精度/预算暴露为新 Canvas 字段。后续若开放配置，须同步三端校验、版本门槛和 Inspector。
