# 资产登记、发布与元数据同步

## 目标与边界

资产模块保存“发布治理记录 + 原资源安全元数据快照”，用于把已有业务资源组织成适合门户发现的资产。原资源仍是事实来源，资产记录不是业务数据副本，也不接管原资源的生命周期和操作能力。

依赖保持单向：资产模块读取模型、文件数据集、全景影像、码表和数据服务的现有 Service；这些来源模块不增加资产字段、按钮、事件或反向依赖。后台负责登记、发布和同步，公开 `/assets` 门户通过资产模块的专用只读接口展示真实的已发布资产。

## 数据模型

`ds_asset` 使用 UUID 主键并继承统一审计时间，不建立 JPA Entity 关联或数据库外键。

| 分类 | 主要字段 | 说明 |
| --- | --- | --- |
| 来源标识 | `asset_type`、`resource_id` | 五类来源；组合唯一，防止重复登记 |
| 发布治理 | `directory_id`、`status`、门户名称与简介、标签、负责人、更新频率、敏感等级、推荐状态 | 由资产后台维护，不回写来源 |
| 来源摘要 | 来源名称、编码、说明、状态和更新时间 | 最近一次成功同步的通用安全元数据 |
| 来源快照 | `source_snapshot`、`source_fingerprint` | 白名单 JSON 与规范化 SHA-256 指纹 |
| 同步状态 | 检查/同步时间、`sync_status`、`sync_error` | 表达当前来源与已保存快照的关系 |

`source_snapshot` 使用 `LONG32VARCHAR` 保存为 PostgreSQL `text`。快照不保存凭据、SQL、脚本、物理存储位置或部署错误，只包含门户展示需要的类型化字段：

- 数据模型：发布状态、数仓分层、Schema 版本、字段数量。
- 文件数据集：数据集类型、文件数量、表数量、可用表数量。
- 码表：启用状态、取值类型、内容版本、码值数量。
- 数据服务：服务类型、访问模式、路由、定义版本、部署状态。
- 全景影像：内容版本、尺寸、原图大小、拍摄时间/偏移、设备摘要和是否有位置；不含精确坐标、原始 EXIF/XMP、图片地址和内部文件引用。

业务领域复用 `DirectoryScope.ASSET`。领域树中的资产数量由 `ds_asset.directory_id` 实时聚合；任何资产引用的领域都不能删除。

## 登记与生命周期

候选查询展示来源资源及其可登记原因，已经登记的资源携带对应 Asset UUID。登记请求会重新读取和校验来源，不能依赖前端禁用状态绕过规则：

- 数据模型必须为 `PUBLISHED`。
- 文件数据集至少包含一张 `READY` 或 `SCHEMA_READY` 表。
- 码表必须启用。
- 全景影像必须有可用当前成品；替换处理中或失败但旧成品可用时仍可登记。
- 数据服务必须为 `ENABLED`。

登记创建 `DRAFT` 并保存首份快照。`DRAFT` 和 `OFFLINE` 可以发布；发布前重新读取来源并要求业务领域、有效名称、有效简介、负责人、更新频率和敏感等级完整。只有 `PUBLISHED` 可以下线；已发布资产不能直接删除，草稿和下线资产可以删除。所有生命周期操作只修改资产记录，不修改或删除来源资源。

门户名称和简介为空时分别回退到来源名称和说明。编辑门户字段、检查或同步均不回写来源；同步也不会覆盖领域、门户覆盖字段、标签、负责人、更新频率、敏感等级、推荐状态和发布状态。

## 检查与同步

检查重新生成当前来源快照并比较指纹，只更新检查时间与同步状态，不覆盖最后成功快照。同步在来源可用时覆盖来源摘要、快照和指纹，并更新最后同步时间。

| 状态 | 含义 |
| --- | --- |
| `IN_SYNC` | 当前来源指纹与保存快照一致，或同步刚成功 |
| `OUTDATED` | 检查发现来源元数据发生变化 |
| `SOURCE_UNAVAILABLE` | 来源存在，但当前生命周期状态不满足发布条件 |
| `SOURCE_MISSING` | 来源资源已不存在 |
| `FAILED` | 读取或生成来源快照失败 |

来源不可用、缺失或读取失败时保留最近一次成功快照，且不自动改变资产发布状态。全量检查和全量同步只遍历已登记资产，每条资产独立读取、独立提交并容错，响应汇总正常、待同步、不可用、缺失和失败数量以及失败摘要；不会自动登记或发布来源资源。

## 管理 API

查询使用 `asset.view`，候选与所有变更命令使用 `asset.manage`：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/assets` | 使用统一 Search API 查询资产 |
| `GET` | `/api/v1/assets/{id}` | 查询治理信息与安全快照 |
| `GET` | `/api/v1/assets/candidates` | 分类型、关键词和分页查询候选 |
| `POST` | `/api/v1/assets/actions/register` | 批量登记资产草稿 |
| `POST` | `/api/v1/assets/{id}/actions/update` | 修改门户治理字段 |
| `POST` | `/api/v1/assets/{id}/actions/publish` | 发布资产 |
| `POST` | `/api/v1/assets/{id}/actions/offline` | 下线资产 |
| `POST` | `/api/v1/assets/{id}/actions/delete` | 删除资产记录 |
| `POST` | `/api/v1/assets/{id}/actions/check` | 检查单条资产 |
| `POST` | `/api/v1/assets/{id}/actions/sync` | 同步单条资产 |
| `POST` | `/api/v1/assets/actions/check-all` | 全量检查已登记资产 |
| `POST` | `/api/v1/assets/actions/sync-all` | 全量同步已登记资产 |

业务领域查询继续使用 `directory.view`，领域维护使用 `directory.manage`。

## 公开资产门户

门户首页和详情页分别使用 `/assets` 与 `/assets/{id}`。匿名用户可以浏览全部 `PUBLISHED` 资产；`DRAFT` 与 `OFFLINE` 不参与概览、领域计数、列表、搜索和详情。`PUBLIC`、`INTERNAL`、`SENSITIVE` 都可展示，敏感等级用于醒目标识，不作为门户可见性规则。

公开接口不使用管理端 Search DSL：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/asset-portal/overview` | 已发布总数、五类数量、热门真实标签、顶级领域与后代已发布数量 |
| `GET` | `/api/v1/asset-portal/assets` | 按关键词、资产类型、业务领域和分页查询已发布资产；领域包含全部后代 |
| `GET` | `/api/v1/asset-portal/assets/{id}` | 查询公开治理信息及实时或缓存的来源安全元数据 |
| `GET` | `/api/v1/assets/{id}/source-navigation` | 登录后按来源类型校验查看权限并返回现有前端详情路径 |

列表固定按推荐状态、发布时间和 UUID 倒序，默认每页 12 项，最多 48 项。关键词只匹配有效名称、有效简介、来源编码和标签。门户响应不返回来源资源 UUID、同步错误、SQL、脚本、凭据、物理存储位置或其他管理字段。

详情读取不修改资产的同步状态、检查时间、保存快照或发布状态。来源可用时返回实时安全元数据；来源存在但不满足可用条件时返回实时元数据并标记 `UNAVAILABLE`；来源缺失或读取失败时返回最近成功快照并标记 `CACHED`。门户名称和简介始终优先，未覆盖时才使用实时来源值或保存快照。

“使用资产”不是匿名直达原管理接口。匿名用户先登录并保留当前详情地址；登录用户再调用来源导航接口，接口分别检查 `model.view`、`filedataset.view`、`standard.dictionary.view` 、`panorama.view` 或 `service.view`，通过后才返回原资源页面路径。

全景来源导航为 `/panorama/{id}`。替换后继续使用来源指纹检查与同步，删除来源保留资产与缓存快照；完整范围见 [全景影像管理 V1](../development/panorama-management-v1.md)。
