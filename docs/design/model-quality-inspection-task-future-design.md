# Spark 模型质检任务设计与实现边界

## 1. 文档目的

本文记录模型质量检查执行能力的当前实现边界。系统已经实现质量规则定义管理，以及基于
`SPARK_MODEL_QUALITY` 的手动、Cron 全模型质检，以及失败规则的受控 Parquet 样本；数据变化信号、
增量范围、全量异常、自动脱敏、告警和问题闭环仍属于后续能力。

## 2. 核心决策

质量规则继续属于模型，用来定义“检查什么”；实际数据检查统一由独立的“质检任务”执行。

```text
模型质量规则
      ↓ 被引用
独立质检任务
      ↓ 产生
质检运行记录与规则结果

手动操作 ─────┐
定时计划 ─────┼→ 触发质检任务
数据变化信号 ─┘   （后续阶段）
```

质检任务与现有批处理任务、实时任务保持松耦合：

- 数据任务不直接执行质量规则，也不等待质检结果。
- 质检失败默认不改变原数据任务的成功状态。
- 实时任务不因质检产生反压或中断。
- APPEND、UPSERT、实时窗口和外部表等数据变化暂不引入复杂的增量边界计算。
- 质量结果可以关联数据任务运行或变化信号，用于定位来源，但不把质检作为数据任务的固定尾部节点。

## 3. 第一阶段范围

第一阶段新增独立质检任务，只支持以下触发方式：

- 手动触发：技术人员点击“立即执行”。
- 定时触发：按照质检任务配置的 Cron 计划执行。

第一阶段统一执行目标模型的全量检查，不支持增量、分区、水位线、Checkpoint 或实时微批范围检查。

一个质检任务包含：

- 名称、说明和启用状态。
- 一个目标模型。
- 规则范围固定为目标模型当前全部启用且有效规则。
- 可选的 Cron 定时计划。
- 手动执行入口。

一个模型允许创建多个质检任务，以支持不同周期；v1 不配置规则子集，不为单条质量规则分别配置调度。

每次执行开始时读取当前规则定义，并把本次实际使用的规则配置保存为运行快照，避免后续规则修改改变历史结果语义。

## 4. 运行记录与结果

每次执行复用 `task_run`，保存触发、Spark 状态和质量汇总。完整规则结果只保存在受保护的
`result.json`，不新增规则运行明细表：

- 质检任务、目标模型。
- 触发方式，定时触发时保存计划信息；v1 不保存触发人。
- 可选的关联信号和来源运行标识。
- 开始时间、结束时间和执行耗时。
- Spark 状态沿用 `QUEUED / RUNNING / SUCCESS / FAILED / TIMED_OUT / CANCELLED / SKIPPED`。
- Spark 正常完成时单独保存质量结论 `PASSED / FAILED`；数据不合格不会把 TaskRun 标记为失败。
- 规则总数、通过数、失败数、跳过数和检查行数。
- 本次使用的规则定义快照。

每条实际完成的规则保存独立结果：

- `PASSED`：规则执行完成且数据符合要求。
- `FAILED`：规则执行完成，但异常量超过容忍阈值。
- 检查数量、异常数量、异常比例和执行耗时。
- 行级失败规则可按任务配置保存每条规则最多 `0～1000` 条样本；`0` 关闭，新建定义默认 `100`，
  历史空值按 `0` 处理。行数和新鲜度规则不生成行级样本。
- 样本以每规则一个 Parquet 对象保存到既有任务制品 Bucket：
  `task-runs/{runId}/attempts/{attempt}/quality/samples/{ruleId}.parquet`。
- Result 只保存样本数量、异常总数、截断标志、大小、SHA-256、字段元数据和可定位性，不保存对象 Key
  或业务值；Admin 必须通过运行和规则 ID 推导对象 Key。
- 单文件最大 20 MiB、单运行全部样本最大 100 MiB；生成、上传或完整性校验失败属于技术失败，
  不生成质量结论。Binary 和 Geometry 原值不进入样本，字符串最多保留 4096 字符。
- 预览由 Admin 下载受控 Parquet 临时解析后返回，第一版不引入 DuckDB、CSV、服务端筛选或样本表；
  `task.view` 用户可预览和下载，页面必须提示样本可能包含业务数据。

连接、读取、Spark 计算或表达式错误属于整次运行的技术失败：TaskRun 进入 `FAILED/TIMED_OUT/CANCELLED`，
质量结论和汇总为空，不为失败或未完成规则伪造 `PASSED/FAILED/ERROR` 指标。`result.json` 可以保留
失败前已完成的规则、跳过规则，以及失败规则 ID、名称、类型、严重程度、耗时和诊断 ID；失败规则
上下文不含字段实际值，并与顶层安全错误使用同一个诊断 ID。`QUALITY_RULE_FAILED` 安全日志使用相同
诊断上下文，便于技术人员定位。

数据不符合规则与质检执行错误必须严格区分，不能用同一个“失败”状态混合表达。

## 5. 模型质量概览与最近规则结果

模型详情的“质量规则”页签同时提供紧凑质量概览，但不新增规则结果数据库表。查询口径固定如下：

- `task_run.quality_target_model_id` 保存运行创建时的目标模型快照，任务后来更换模型不会改变历史归属。
- 最近运行按 `queuedAt` 选择，用于提示正在排队、运行、技术失败、超时、取消或跳过的最新状态。
- 最近有效结果按 `endedAt` 选择该模型最近一次 `SUCCESS` 且具有质量结论和规则快照时间的运行。
- 概览汇总与全部规则明细必须来自同一次有效运行；最新运行未产生质量结论时，继续保留上一次有效结果。
- 升级前没有目标模型快照和规则快照时间的运行不回填，也不进入模型质量概览。

管理库只保存运行汇总。规则状态、强类型指标、跳过原因和非敏感样本描述按需从最近有效运行的一个
`result.json` v4/v5 读取，并校验运行身份、执行尝试、成功状态及汇总一致性。对象存储不可用、Result
缺失或损坏时，页面继续展示数据库汇总并明确标记规则明细暂不可用，不回退到更早制品。

当前规则的 `updatedAt` 晚于本次 `quality_rule_snapshot_at` 时，旧结果仍展示并标记“配置已变更”；
当前新增且未出现在该运行中的规则显示“未检查”。运行后已经删除的规则只进入可展开的历史规则结果，
用于解释原始汇总，不重新混入当前规则管理列表。

查看概览与规则指标复用 `model.view`。只有同时具有 `task.view` 时，页面才提供准确运行详情深链以及
失败样本预览、下载入口；运行详情使用 `tab=runs&runId={runId}` 定位，关闭详情时只移除 `runId`。

## 6. 后续数据变化信号

数据变化信号作为后续阶段能力，第一步仅保存和展示，不自动触发质检。

信号建议包含：

```text
modelId
sourceType
sourceId
sourceRunId
writeMode
occurredAt
summary
```

信号可能来自批处理任务、实时任务窗口、数据录入、外部同步或其他写入流程。技术人员可以在质检任务中查看尚未处理的数据变化，根据来源、时间、写入方式和摘要，人工作出以下选择：

- 立即重新检查。
- 标记为已知悉或忽略。

后续确有稳定需求时，再给质检任务增加信号策略：

- `RECORD_ONLY`：只记录和提醒，作为默认策略。
- `AUTO_RUN`：收到符合条件的信号后自动执行。

在引入自动触发前，需要另行确定信号去重、合并、防抖、积压处理、目标模型就绪条件以及 APPEND、UPSERT、实时窗口的检查范围。

## 7. 页面建议

质检任务复用现有任务中心和目录，不新增左侧菜单。任务详情只展示基本信息、质检定义、定时计划和运行记录；运行详情展示 Spark 状态、质量汇总、规则指标、跳过原因、Tracking URL及受保护制品下载。

模型详情中的“质量规则”页签负责规则定义管理和模型最近质量状态展示，包括：

- 当前规则的最近一次结果和配置变更提示。
- 最近一次有效质检概览以及最新运行状态。
- 具有任务查看权限时进入来源任务运行，并查看可用的失败样本。

信号能力实施后，在质检任务详情增加“数据变化信号”区域，展示待处理信号及人工操作入口。

## 8. 暂不实施

以下能力不纳入第一阶段：

- 将质检强制绑定到现有数据任务尾部。
- 质检失败后回滚、删除或隔离已写入数据。
- 实时逐条、逐微批或逐 Checkpoint 质检。
- APPEND、UPSERT、分区或时间窗口增量检查。
- 跨模型依赖就绪编排。
- 信号自动触发、合并和防抖。
- 质量发布门禁、告警和问题工单闭环。
- 规则或质检任务版本管理。

## 9. 推荐实施顺序

1. 建立质检任务、质检运行和单规则结果数据结构。
2. 实现手动触发的全模型检查，验证现有规则的真实执行语义。
3. 增加模型级 Cron 定时执行。
4. 完善运行详情、异常统计和安全的失败样本展示。（已实现 v1）
5. 接入数据变化信号的保存、展示、知悉和人工重新检查。
6. 根据真实使用情况，再决定是否实现自动信号触发和增量检查。

## 10. 最终结论

质量规则负责定义标准，独立质检任务负责执行。第一阶段仅支持手动和定时全量检查；数据变化信号后续先作为技术人员可见、可确认的事实记录，由技术人员判断是否重新检查。整个质检能力不与现有批处理任务或实时任务形成强耦合。
