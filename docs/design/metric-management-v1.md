# 数据指标管理 V1：指标口径与结果模型关联

状态：已实现指标元数据管理及 Excel 导入导出；本期不包含指标数据结果查询。适用于指标管理、发布版本、结果绑定、模型/任务关联及离线口径整理功能。页面联调不作为本文已完成验证的声明。

依据：[工程约定](../../AGENTS.md)、[模型管理](model-management.md)、[血缘契约](lineage-integration-contract.md)、[前端交互规范](../development/frontend-ui.md)。

## 1. 本期能力与边界

指标记录“业务含义、采用什么口径、结果在哪里”；实际 SQL、Canvas 和 Spark JAR 计算仍在已有任务中维护。

```mermaid
flowchart LR
    Source[一个或多个来源模型] --> Task[现有计算任务]
    Task --> Model[目标模型]
    Metric[指标口径及发布版本] --> Binding[结果模型与字段绑定]
    Binding --> Model
    Task -.通过输出模型反查.-> Metric
```

本期提供：指标目录与检索、基础登记、口径编辑、草稿、发布/停用、历史快照与差异、结果位置登记、模型和任务反查、参考服务导航、元数据诊断及引用保护，以及 Excel 模板、导入预览与口径导出。

本期不提供：指标“数据结果”页签、正式结果查询、草稿结果预览、外部物理表检查、公式解析、自动任务生成、自动重算、指标专用调度、成果确认、水位和告警。指标模块不访问业务物理表，也不引入 MetricResultService。已有模型页面的数据预览沿用原功能。

## 2. 指标与计算的连接

- 指标 → 目标模型 UUID → 数值字段 UUID；时间、维度及固定条件解释结果每一行的含义。
- 任务 → 现有输出模型关系 → 该模型绑定的指标；不保存任务—指标生产关系表。
- 一个模型可以承载多个指标，一个任务可以关联多个模型，一个指标可以反查多个任务。
- 一个指标发布版本最多绑定一个结果模型和一个数值字段；不同结果粒度分别登记指标。
- 指标可先登记完整口径并发布，结果绑定允许以后补充。
- 来源、相关指标和服务只是实施说明及导航，不构成计算依赖图。

指标发布不会读取任务脚本、触发任务、修改调度或证明计算实现与业务口径一致。任务编辑、停用、删除或重新运行不自动修改指标版本。

## 3. 基础资料与定义

基础资料包括 code、name、kind、directoryId、ownerName、summary。编码采用 `[a-z][a-z0-9_]{0,63}`，创建后不可修改；名称最长 100，负责人最长 100，简介最长 1000。kind 为 ATOMIC / DERIVED / COMPOSITE，仅作为业务分类，首次发布后固定。

名称、目录、负责人和简介直接维护；口径与结果绑定通过草稿发布。

| 定义内容 | 字段 |
| --- | --- |
| 业务含义、计算口径、统计范围 | businessMeaning、calculation、statisticalScope |
| 时间口径、周期及字符串格式 | timeDescription、statisticalPeriod、periodFormat |
| 来源与结果粒度 | sourceGrain、grainDescription |
| 单位、空值处理、汇总说明、更新说明 | unit、nullHandling、aggregationDescription、updateDescription |
| 数值显示 | decimalPlaces（0～10）、valueFormat（NUMBER / RATIO / PERCENT_VALUE） |
| 结果位置 | binding |
| 可选参考 | references |

统计周期为 NONE / DAY / WEEK / MONTH / QUARTER / YEAR。文字口径不解析为表达式；更新说明不替代任务调度。RATIO 表示 0～1 比值，PERCENT_VALUE 表示百分数值，本期仅登记这种解释方式。

发布前要求负责人、业务含义、计算口径、统计范围、单位、结果粒度、空值及汇总说明完整；时间型指标还需要时间口径。来源粒度和完整来源清单不作为发布前置条件。

## 4. 结果绑定

| 内容 | 规则 |
| --- | --- |
| modelId | 一个已发布 MANAGED 或 EXTERNAL 模型 |
| valueFieldId | 同模型的数值字段，使用平台数值类型 |
| periodFieldId | 时间型指标必填，支持 DATE / TIMESTAMP / TIMESTAMP_NTZ / STRING |
| dimensions | 最多 20 个；每个维度有唯一 key、名称、说明及字段 UUID |
| supportingFieldIds | 最多 4 个辅助解释字段 |
| fixedFilters | 最多 8 个固定 AND 条件 |

所有结果字段必须属于同一模型。STRING 时间需要声明 periodFormat（例如 yyyy-MM）；这里只校验格式定义，不解析业务数据。维度使用唯一小写编码，不重复绑定字段，不使用空间或二进制类型。

固定条件支持 EQ、NE、GT、GE、LT、LE、IS_NULL、IS_NOT_NULL，条件值以字符串提交并按模型字段类型校验；空值运算符不接收非空值。条件不编译为 SQL、不执行筛选。时间点按带偏移时间、TIMESTAMP_NTZ 按本地时间语义验证。

平台不扫描全表验证粒度唯一，也不推断模型上未登记的业务维度。维护者负责说明完整粒度或用固定条件限定范围。

### 4.1 宽表与长表

- 宽表：月份、地区、paid_amount、refund_amount、net_amount。三个指标分别绑定各自数值列，共用月份和地区。
- 长表：月份、地区、metric_code、metric_value。多个指标共用 metric_value，分别设置 metric_code = paid_amount 或 refund_amount 等固定条件。

模型与数值字段组合没有全局唯一约束。长表字段命中不能证明写入了哪些 metric_code，也不能证明覆盖全部目标行。

## 5. 草稿与版本

| 操作 | 行为 |
| --- | --- |
| 创建 | DRAFT，生成空定义及草稿摘要 |
| 保存草稿 | 接收类型化定义及 expectedDraftFingerprint；允许未填写完整口径，返回诊断 |
| 发布 | 校验已保存草稿及结果引用，生成不可变快照并切换当前版本 |
| 重复发布 | 定义及结果绑定契约均相同时复用最近版本 |
| 停用 | DISABLED，保留口径与历史，不改变任务状态 |
| 再次发布 | 重新校验后启用；内容一致可复用最近版本 |
| 恢复更早口径 | 形成新的递增版本 |
| 删除 | 只允许删除从未发布的指标 |

草稿保存与发布均校验预期摘要，过期提交返回 409。发布在管理库短事务中锁定指标与结果模型，再保存快照和引用投影。新建或替换引用需对应资源查看权限；新引用不存在或字段归属非法时拒绝保存。原引用后来失效时保留说明并返回诊断，允许逐步修复。

发布快照保存定义、当时资源名称/编码、类型/物理定位的解释契约、发布人和变更说明；不保存任务版本、SQL、JAR、连接凭据或业务结果值。历史快照不表示历史物理数据。

## 6. 关联查询与证据

复用 TaskModelRelationQueryService 的当前已保存定义及输出位置：

- LOCAL_SQL：明确的 outputModelId。
- Canvas：已有 OUTPUT 模型引用。
- Spark JAR：MODEL 资源的 WRITE / READ_WRITE 权限声明。
- 只有 INPUT 的任务不作为写入任务；没有直接输出定义的任务不推断子任务的产出。

模型/任务关联列表默认使用当前 PUBLISHED 指标；有 metric.manage 时可切换 DRAFT 或 DISABLED。关系查询使用有界分页，按指标去重并保留输出模型与定义版本。

有可用的现有输出字段血缘时，按实际定义版本标注。旧版本证据单列，不作为当前字段命中依据。不增加 SQL/JAR 分析器；未纳管 JDBC 输出没有权威模型对应关系时保持不可解析，不猜测表名。

任务成功、影响行数、资源写权限或字段命中均不证明指标口径正确或结果完整。任务可能只更新部分字段、月份或业务范围，覆盖/删除也可能影响同表其他指标。

任务改变输出模型后，当前关联随查询变化；已有历史血缘仍按其真实版本说明。本期不重建完整历史任务—指标关系，不把当前绑定解释为过去运行时的指标定义。

## 7. 引用保护与元数据诊断

当前已发布启用指标的结果模型及全部实际绑定字段受删除保护，包括值、时间、维度、辅助列和固定条件字段。保护接入模型引用响应、模型删除、字段编辑移除、外部字段整体替换以及物理变更执行前与元数据回写检查。

| 资源变化 | 行为 |
| --- | --- |
| 删除受保护模型/字段 | 返回 409 / MODEL_REFERENCED；先调整绑定并发布或停用指标 |
| 结果模型未发布/已停用 | 保留绑定，显示发布状态诊断 |
| 字段编码、类型或物理目标改变 | 标记 METRIC_RESULT_STRUCTURE_CHANGED，要求修订或重新发布 |
| 模型名称、目录或无关字段改变 | 更新当前说明，不因整体 schemaVersion 改变而一律失效 |
| 草稿、停用或历史绑定 | 不长期阻止资源删除，再次发布时重验 |
| 可选来源、相关指标或服务失效 | 返回非阻断诊断，保留说明与移除入口 |
| 任务变化或删除 | 只改变关系查询，不增加任务删除保护 |

health 只检查管理元数据，bindingStatus 为 UNBOUND / VALID / INVALID；VALID 仅表示绑定元数据有效，不代表业务数据完整。诊断携带 code、path、message、blocking。

## 8. 管理库与模块

Business 的 metric 包实现业务；前端位于 modules/metric。使用现有 BaseEntity、UUID 标量引用、LONG32VARCHAR、SearchEngine、单角色 RBAC 和 ProblemDetail；不新增 Maven 模块、生产框架或执行协议。

| 表 | 内容 |
| --- | --- |
| ds_data_metric | 基础资料、状态、草稿 JSON/摘要、当前或最近发布版本 UUID |
| ds_metric_release | metricId/version 唯一；不可变定义/引用快照、契约摘要、发布事实 |
| ds_metric_reference | DRAFT / CURRENT 确定性投影；资源种类、UUID、字段所属模型、可选参考版本、引用路径及结果绑定标识 |

资源反查索引覆盖 resourceKind/resourceId/scope、父模型和指标引用路径。任务关联不进入引用表。JSON 文本显式排除通用 Search DSL，普通列表仅支持实体标量字段。

现有 DirectoryScope 扩展 METRIC，目录资源计数与非空删除保护复用 DirectoryService；已有 PostgreSQL 枚举检查约束同步机制保持生效。无旧指标数据迁移、无既有任务回填。

本期没有 query-data 或外部物理检查接口。成功响应直接使用 DTO/PageResponse，错误沿用 RFC 9457；400 输入非法、403 权限不足、404 资源不存在、409 状态或绑定冲突。

权限：

- metric.view：指标、发布版本及元数据查看。
- metric.manage：创建、基础维护、草稿编辑/校验、未发布删除及管理状态关系筛选。
- metric.publish：发布、停用，并可读取已保存草稿用于发布审阅。
- Excel 模板、预览、错误清单和确认导入需要 metric.manage；导出需要 metric.view，其中草稿导出还需要 metric.manage 或 metric.publish。
- 新增/替换模型字段引用需要 model.view，服务引用需要 service.view，指标引用需要 metric.view。
- 模型关联视图还需 model.view；任务关联与反查还需 task.view、model.view。对应服务详情继续使用 service.view。
- 模型删除是否允许不受操作者是否拥有 metric.view 影响；无指标查看权限时不返回指标名称摘要。

## 10. 页面与操作流程

- “数据管理 → 指标管理”：目录树、名称/编码、类型、状态、负责人筛选；不在列表展示脱离时间和维度的业务数值。
- 列表工具栏提供“导入”“导出”，支持跨页勾选导出；导入 Drawer 先选文件并预览，再确认整批保存，详见第 13 节。
- 新建 Drawer 保存基础资料后进入口径编辑。
- 口径编辑分为“业务口径、时间与维度、结果绑定、参考资料”，允许保存不完整草稿；候选模型及字段按需搜索分页。发布前必填项在字段标签显示红色 *，顶部说明其含义；初始只显示必填标记和简短占位文字，不因草稿空值展示警告边框或缺失提示。字段经过编辑并失焦后才显示缺失提示，补齐后即时清除；详细示例使用字段旁的 ContextHelp，发布确认统一展示未满足的要求。资源失效等实际诊断仍贴近字段，不在底部堆叠。时间口径、时间格式及绑定字段随配置显示必填标记，保存草稿不受发布必填项限制。
- 详情只有“指标口径、相关任务与服务、发布版本”三个页签。默认显示当前发布口径；从未发布时显示草稿；有待发布变更时单独提示。
- 发布确认展示已保存草稿及诊断，阻断问题解决后才能发布；保存不自动发布。
- 历史快照只读，可以对比两个版本的口径、绑定字段类型和物理位置；模型、任务详情新增“关联指标”页签，导航返回原详情。
- 参考服务在指标定义中选择、移除和查看状态，仅作导航，不创建、代理或发布服务。

使用现有 Ant Design 组件、目录组件、ContextHelp、InlineFeedback、详情分区和蓝紫主题。普通说明贴近字段；列表失败提供持续可见的错误和重试。缓存由 TanStack Query 管理，指标发布、绑定修改及模型/任务变更会失效相关查询。

## 11. 后续阶段

后续如开发指标数据结果，再单独设计正式/草稿查询、绑定字段白名单、固定条件执行、分页、精度和物理诊断；不可把当前“元数据有效”解释为物理结果已验证。

LLM 辅助任务另行设计：优先提供指标口径、结果模型 Schema、来源 Schema、关联与时间语义、已有任务上下文，让 LLM 生成可审阅的 Spark SQL/Canvas SQL_TRANSFORM 提案；复杂算法使用 SDK Java/Spark JAR。当前助手提案未因此新增 SQL_TRANSFORM 支持，也没有指标专属工具或自动执行入口。

## 12. 关联与口径维护示例

以下均为假设资源。

### 12.1 多个指标共用目标模型

目标模型 ads_case_monthly 的粒度为 stat_month × district_code，含 closed_count、on_time_count、on_time_rate 三个数值字段。

| 指标 | 口径说明 | 结果绑定 |
| --- | --- | --- |
| 月度办结件数 | 按完成月份统计有效办件 | closed_count |
| 月度按期办结件数 | 有效办件中满足按期条件的数量 | on_time_count |
| 月度按期办结率 | 按期办结件数 ÷ 办结件数，零分母为空 | on_time_rate |

三项指标绑定同一模型、同一时间与区县维度。比例保存 0～1 原值，可额外绑定分子、分母为解释字段。

实施人员自行在现有 Spark Canvas/JAR 或 LOCAL_SQL 中实现多来源关联和计算。指标说明不参与任务校验或执行。

任务 T 写入 ads_case_monthly，任务页即可通过该模型展示三个关联指标。任务 U 如果只补某个月的按期字段，也会匹配这个模型；已有字段映射可补充解释，但不据此声称整表所有指标都已重算。不同任务关联无需人工逐个登记。

指标详情可以反查 T、U。T 修改、停用或删除，只改变关联和运行状态，不要求重新发布三项指标，也不阻止任务原有生命周期。

“按期”从自然日改成工作日时，维护者修订口径，并自行调整任务及结果范围。系统不自动改脚本、运行任务或重算历史。未来 LLM 可读取这些口径与模型 Schema，辅助生成修改提案。

### 12.2 多来源销售统计的对应关系

采用讨论中的销售例子：订单表提供订单、订单创建月份和下单地区；支付表、退款表分别是一单多笔。实施人员编写任务，先分别汇总支付、退款到订单粒度，再关联订单并按月份、地区汇总，写入目标模型 ads_region_monthly_sales。中间步骤可在一个任务内完成，也可以复用已有中间模型。

本例按订单创建月份归属，成功支付和退款累计到明确统计截止时间；后续月份发生的退款仍归回对应订单月份。该口径与按退款发生月份统计不同，需要写在指标说明中。

| 指标 | 供实施人员阅读的口径 | 结果绑定 |
| --- | --- | --- |
| 月度地区实付金额 | 统计有效订单的成功支付金额，避免一单多笔关联重复 | ads_region_monthly_sales.paid_amount |
| 月度地区退款金额 | 统计相同订单范围截至统计时点的成功退款金额 | ads_region_monthly_sales.refund_amount |
| 月度地区净收款金额 | 实付金额减退款金额 | ads_region_monthly_sales.net_amount |

三项指标共同声明月份、地区字段。平台持久化的是指标口径及这些结果绑定；输入表关联、条件、聚合和差值表达式由任务保存。来源说明可以作为参考资料补充，但不要求在指标域复制该任务的计算图。

| 任务的已有输出信息 | 指标页/任务页的关联展示 |
| --- | --- |
| T1 输出 ads_region_monthly_sales | 通过该模型查询到上述三个当前已发布指标 |
| T2 仅补同一模型的退款字段或某个月份 | 保留模型关联，已有证据可补充“退款字段涉及”；不宣称三个指标完整更新 |
| T3 只读取该模型，输出其他模型 | 不列为该模型的写入任务 |
| T1 改为输出另一个模型 | 当前关联按新目标重新查询，不修改任何指标的口径或结果绑定 |

实施人员在 T1 中不需要勾选三个指标，也不需要维护 T1 与三个指标版本的对应表。指标的结果字段绑定建立后，模型和任务页面即可按上述规则查询关联。

### 12.3 修改口径后的职责

例如退款口径从“退款成功”改为“退款成功且已到账”：

1. 指标维护者修订并发布口径说明；平台保留说明和结果绑定历史。
2. 通过结果模型查看相关任务，实施人员判断哪些计算实现需要调整；模型级关系只提供排查入口，不替代业务判断。
3. 实施人员在现有任务中调整条件，按原流程处理任务发布、调度和需要重算的数据范围。
4. 结果模型及绑定字段未改变时，任务仍可按模型反查到该指标；任务版本不需要写回指标定义。

上述步骤表达职责，具体切换时序由实施人员结合实际数据安排。仅修改或发布指标说明不会改变任务脚本，也不能表示已有数据已采用新口径；需要并行验证或保留旧口径数据时，使用独立结果模型或明确固定条件隔离结果范围。

## 13. Excel 导入导出与线下整理

适用范围：批量整理指标基础资料和文字口径。结果模型、字段 UUID、维度绑定、固定条件及参考资源继续在系统内维护，Excel 不导入或清空这些配置，也不查询业务数据。

### 13.1 操作流程

新增指标：在指标列表点击“导入 → 下载模板”，填写“指标”工作表，一行一个指标；选择文件后点击“预览校验”。预览列出新增、更新、无变化和错误行数，展开行可查看字段修改前后的内容及发布前提示。修正错误后重新选择文件、预览并确认导入。

更新已有指标：先在列表筛选或跨页勾选，点击“导出”，选择默认的“草稿（线下编辑）”；在该文件内修改资料和口径后回导。改变已应用筛选或目录会清空勾选；未点击“查询”的筛选输入不影响导出范围。有勾选时导出这些指标，否则导出当前筛选范围的全部页。勾选对象已删除或已不符合筛选条件时提示刷新，不静默漏导。

口径没有填写完整仍可导入。发布所需的缺失项以非阻断提示展示；编码重复、名称缺失、类型非法、目录无法匹配、字段超长或导出基线过期等错误阻止整批导入。错误清单另存为 Excel，包含原工作表行号、指标编码、列名、级别和问题说明。预览不会保存指标或暂存记录。

确认导入直接更新名称、类型（尚未发布时）、目录、负责人及简介；口径仅更新草稿，状态和历史发布版本保持原状。完成后刷新指标列表与目录计数。需要正式采用修改后的口径时，继续使用原有发布流程；导入不会触发发布、启用或计算任务。

### 13.2 文件与字段规则

仅支持 `.xlsx`，单文件最多 10 MB、1000 个非空数据行；单次导出最多 1000 个指标，超限时缩小范围。公式和错误单元格不会执行或求值，须先粘贴为值。空行跳过，隐藏行或筛选隐藏的行仍属于文件内容并参与导入；需要排除的指标应删除整行。

工作簿包含“指标”和“填写说明”两个工作表。后者保存模板格式标识 `DATASCALPEL_METRIC_V1`、导出模式、字段规则和假设示例；示例不混入导入数据。保留工作表名称、格式标识、模式和完整表头，可调整列顺序。类型、统计周期和数值显示提供中文下拉选项，导入也接受相应枚举编码。

| 内容 | Excel 列与规则 |
| --- | --- |
| 导入必填 | 指标编码、指标名称、指标类型，表头带 `*`；发布所需的其他字段允许暂空 |
| 基础资料 | 目录路径、业务负责人、简介 |
| 业务口径 | 业务含义、计算口径、统计范围、来源粒度、结果粒度 |
| 时间口径 | 统计周期、时间口径、字符串时间格式 |
| 数值及说明 | 单位、空值与零值、汇总说明、更新说明、显示小数位、数值显示 |
| 隐藏标识 | 指标 ID、草稿摘要、资料摘要；更新已有指标必须保留，新指标留空 |
| 只读信息 | 指标状态、发布版本；修改这些单元格不会修改系统状态或版本 |

空白单元格表示清空对应可选内容，不能用删除列表示“保持不变”。统计周期、小数位、数值显示留空时分别采用“无周期、2、普通数值”。文本首尾空白会去除；字段长度和编码规则与在线表单一致。小数位按单元格实际数值校验 0～10 的整数，不因 Excel 显示四舍五入而接受小数。

目录使用已有指标目录的完整路径，以 `/` 分隔。留空归入未分类；目录不存在、路径不明确或目录结构无法解析时返回错误，不自动创建目录。

### 13.3 两种导出模式

| 模式 | 内容及用途 |
| --- | --- |
| DRAFT／草稿 | 当前基础资料和已保存草稿，包含未发布修改及隐藏的基线信息；用于线下编辑后回导 |
| PUBLISHED／当前发布口径 | 当前基础资料与最近发布版本的口径，附状态、版本号；供审阅和查阅，不能直接回导 |

发布口径模式包含曾经发布、当前停用的指标，并如实标注状态；未发布指标不进入按筛选范围导出的发布口径文件。显式勾选了未发布指标时提示调整选择或导出草稿。发布口径文件缺少草稿更新基线，不能通过修改模式标识用于覆盖草稿。它是当前资料与发布口径的清单，不是完整历史资料快照或系统迁移备份。

### 13.4 更新识别与整批提交

使用不可变指标编码匹配：系统不存在则新增，存在则更新。新增行使用模板空白行；不可直接复制已有指标的隐藏标识再修改编码。已有指标的更新必须来自该指标的草稿导出行，手工输入相同编码但缺少基线时提示重新导出，防止无意覆盖线上资料。

导出基线包含指标 UUID、草稿摘要及基础资料摘要；基础资料摘要覆盖名称、类型、目录、负责人、简介、状态和当前发布版本引用。导出后上述资料或草稿发生变化，离线文件的更新行会被拒绝，需要重新导出后合并修改。

预览响应返回 `fingerprint`，由文件内容及匹配到的当前指标、草稿/资料摘要和解析后的目录 UUID 生成。确认请求以 multipart 提交相同 `file` 及 `expectedPreviewFingerprint`；服务端按编码顺序锁定并刷新已有指标，再重新校验。文件或指标状态变化时返回 409，要求重新预览；导出基线已过期时还需要重新导出整理。

预览存在任一错误就不执行写入。通过校验后，整批调用已有基础维护和草稿保存能力，在同一个管理库事务内提交；后续任何一行保存失败均回滚本批修改，无变化行不更新。绑定和参考资源从当前草稿保留，导入权限不会代替发布权限或其他资源的查看权限。

例如，把“月度按期办结件数”的计算口径从自然日改为工作日：导出草稿、修改计算口径、预览差异并导入后，当前发布口径和 `ads_case_monthly.on_time_count` 绑定不变，草稿中保留该绑定并记录新说明。维护者审阅并发布，实施人员再按既有任务流程调整计算实现。
