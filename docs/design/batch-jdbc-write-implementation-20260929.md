# 批处理写入实施方案（2026-09-29）

本文件确定本轮实施边界，承接[讨论稿](batch-jdbc-write-atomicity-and-overwrite-design.md)。已完成数据库原生预研、共享写入内核、Canvas/SDK 接入和 102 正式任务执行；逐项证据及尚未验收的边界见[验证报告](../verification/batch-jdbc-write-20260929.md)。不把 SQL 实验等同于平台完成。

## 1. 已执行的预研

102 上实际启动 Oracle 23ai Free、SQL Server 2019、openGauss 7.0 RC3、ClickHouse 25.8 测试容器；PostgreSQL 16.4/PostGIS、MySQL 8.4.11 沿用已运行容器。不变更数据库全局隔离参数。实验只创建随机专属表，正常与异常结束均清理自己的对象。

`scripts/research-batch-write.py --remote --rows 1000000`：每行 bigint、整数分组、128 字符载荷；目标有主键。数字包含 SSH/CLI 往返，不是纯执行计划耗时，也不是 Spark 端到端吞吐。

| 百万行操作 | PostgreSQL 秒 | MySQL 秒 |
| --- | ---: | ---: |
| 中间表内部装载 | 2.014 | 8.003 |
| 最终 DELETE + INSERT + COMMIT | 4.413 | 9.427 |
| 集合式 UPSERT（全部匹配） | 7.352 | 4.301 |
| 约束失败回滚后的目标行数 | 1,000,000 | 1,000,000 |
| 删除未提交时另一连接查询 | 旧 1,000,000 行，0.234 秒 | 旧 1,000,000 行，1.532 秒 |

PostgreSQL 条件覆盖 1%（未加分组索引）约 0.948 秒。影子装载含主键约 2.186 秒，改名事务约 0.189 秒；但是已有视图仍指向改名后的旧表，不能用于保持原服务依赖的通用覆盖。

`scripts/research-write-capabilities.py`：Oracle、SQL Server、openGauss 实际验证建中间表、集合 MERGE、DELETE/INSERT 后 ROLLBACK 均保留原来的一行。后续 JDBC/Spark 测试另验驱动绑定，不以 CLI 成功代替。

ClickHouse 的 EXCHANGE 在此环境真实失败：宿主内核 3.10 不支持所需交换文件操作（要求 Linux 3.15+）。本轮不为写入改造升级 102 操作系统，不降级成有数据空窗的两次改名。瀚高、金仓、达梦没有本次可验证实例，不冒充已经验证。

## 2. 确定的语义

- **新增显式原子批写能力，缺省继续旧 DIRECT**，避免旧任务突然需要 CREATE/DROP 权限。新 UI 可以选择原子提交；不支持时失败，不暗降级。原子提交只能用于批处理。
- APPEND、UPSERT、OVERWRITE 共用一个中间装载/事务提交内核。一次输出一笔事务，不承诺多个输出、多个数据库统一回滚。
- OVERWRITE 分全部/条件。条件使用目标字段的类型化 AND/OR 树，不开放 SQL 文本；字段必须参与映射。输入越界（包括谓词 UNKNOWN）在删除前失败。
- 原子覆盖默认空输入报错保留旧数据，显式允许才清空范围。旧 DIRECT 空输入语义不变。
- Geometry 继续现有 Sedona/WKB → 数据库原生 Geometry 路线；EPSG 来自任务目标快照，NULL、XY 和不自动转换坐标的原则不变。模型 SDK 复用此路线；自由 JDBC SDK 必须明确给出写入 EPSG，不能从物理目录猜测任务空间语义。
- 试运行继续拦截真实写入，不创建中间表、不删除、不合并。

## 3. 分区重试与最终提交

普通物理中间表增加一个随机命名的内部尝试标识列；每个 Spark partition invocation 使用新的 UUID。分区只写中间表，返回成功标识与该尝试装载行数。Driver 只接受 Spark 最终返回的成功尝试，写入独立的小型成功标识表，最终 SELECT 与此表 JOIN。失败/推测尝试已写的数据不进入目标。APPEND 的合法重复行不去重；不依赖关闭推测执行或恰好总行数。

分区批次只影响暂存数据，可分批提交；最终目标由单连接执行集合式 SQL 并 commit。DDL 在事务外完成。UPSERT 在数据库中检查选中尝试的 NULL/重复键，使用数据库自身比较语义。不会为观测额外 count 源 Dataset。

提交调用前失败应 rollback；进入 commit 后通信失败视为结果待确认，禁止自动重放、不声称已回滚，保留对应暂存证据。提交确认后清理失败不推翻成功。只有本次创建成功的随机对象允许清理；不按全库表名前缀扫删。

## 4. 方言、结构和性能

沿用现有 DatabaseDialect 注册体系作为入口，Dialect 内的 staging 策略工厂按实际数据库实现构造中间表和集合 DML，Task Engine 负责 Spark/生命周期编排，SDK 只保留公开配置，不引入新 Maven 模块或第三方框架。

中间表只投影待写列，用各库原生 SELECT 建表保留数据库类型与比较语义；不克隆主键、外键、默认值、identity、触发器或授权，也不通过平台类型往返“推测”原生类型。针对特殊类型、生成列、collation 和 Geometry 做实测，无法保存所需语义的类型拒绝而非偷偷改类型。最终目标对象、约束与服务引用保持原样。

OVERWRITE 在创建中间表之前检查引用目标的外键；发现 ON DELETE CASCADE / SET NULL / SET DEFAULT 或未知删除规则就拒绝，避免成功覆盖时误删、误改关联表。RESTRICT/NO ACTION 继续由数据库执行约束，违反时回滚。不自动关闭约束或重建关联表。数据库触发器仍是项目部署边界，不能把“保留触发器定义”误说成“不会执行触发器副作用”。

第一批开放 PostgreSQL、MySQL/InnoDB、Oracle、SQL Server、openGauss，五种已通过 JDBC/Spark 实测；具体版本与数据类型范围见验证报告，不表示所有厂商版本、特殊类型均已覆盖。MySQL 实际检查目标存储引擎。非事务触发器副作用和业务外部副作用不作回滚承诺。SQL Server 普通读的锁等待按原库配置，不能声称所有数据库都不阻塞读取。

本轮不自动启用通用影子表改名。已有实测证明它不是无条件正确的优化；ClickHouse 的原生交换在当前主机又不成立。保留研究结论和清晰拒绝，不交付名义上“支持全部数据库”的危险开关。大表按实际覆盖规模、索引和日志成本评估，不设臆测的行数阈值。
