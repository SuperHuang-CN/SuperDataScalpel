# Service Engine 轻量多副本运行

## 范围与部署

复用已有 PostgreSQL，未引入 Redis、消息队列、注册中心或新的生产依赖。只处理 Engine 运行配置一致性和恢复，不改变服务编写、查询协议、脚本返回/事务语义，不适配 APISIX。

| 项目 | 要求 |
| --- | --- |
| 逻辑 Engine | Admin 登记一次；多个 JVM 使用相同 `data-scalpel.engine.code` 和管理 Token |
| 运行库 | 同组共享一个 PostgreSQL 库；不同组分库，不访问 Admin 库 |
| API Studio | 同组 `spring.super-api-studio.service-name` 相同；`cluster-type: None`，不用 Redis 广播 |
| 节点身份 | `/internal/v1/runtime` 的 `instanceId`，每次进程启动变化 |
| 管理地址 | Admin 中 Engine 管理地址可以填写内网 LB 地址；放行 `/internal/v1/**` 并转发 Bearer Token |
| 执行地址 | Engine runtime 地址使用内网 LB 地址供网关转发；与网关自身入口 LB 是两层 |
| 接流量条件 | 对每个节点检查 `/actuator/health/readiness`，仅向 HTTP 200 的节点分流；不能只检查端口或 `/internal/v1/info` |

多副本不等于整套高可用：入口 LB、PostgreSQL、业务数据库也需要部署保障。本改造不提供数据库主从切换或 LB 本身的高可用。普通 Nginx 是否具备主动 HTTP 健康检查取决于部署实现，不应假定写一个 upstream 就会自动处理 readiness。

首次升级：维护窗口停旧进程、备份运行库，先启动一台检查新增 `ds_engine_cluster_state` 表和 readiness，再启动副本。沿用 `ddl-auto=update`，避免首次同时修改表结构。不要混跑旧版本；回滚先停全部新副本，再恢复单实例，不能关闭协调后继续多副本共享库。

## 性能和一致性

- 正常请求只读取本机路由、数据源类型、访问策略，不逐请求查配置库或获取集群锁。
- 单后台线程默认每秒检查全局修订号。无变化不重建路由/池；变更时加载共享快照，内容相同的数据源复用连接池。
- 配置命令持有 PostgreSQL **会话级** advisory lock，占用一条连接而不是一个覆盖整个命令的数据库事务。Engine 自有状态读写使用短事务；内嵌 API Studio 的既有数据源保存实现仍在其事务中尝试连接，本次不改写该外部组件。竞争返回 409，不无限排队。
- 命令前后更新持久化版本，断连或崩溃后不依赖“收到一次广播”。API Studio 原有通知扩展点只提交修订号；副本不反向重新发布旧脚本。
- DataScalpel 部署快照是其托管脚本的最终来源，不要在 Studio UI 同时修改这些托管脚本。
- 单个业务数据源连接失败记入既有健康信息，清除该项旧连接配置，不阻止其他服务。标准/SQL 引用未加载的数据源返回 503；重连沿用 API Studio 既有健康任务（默认一分钟），也可修正后重新注册。首次批量装载仍可能等待连接尝试。

配置成功表示操作已持久化、响应节点已执行本地同步尝试，**不是全部副本同时生效的确认**。常态传播约为一个轮询间隔加装载时间；检测到变化前，其他节点可能短暂执行旧版本。

同步期间、同步失败或最后一次确认超过默认 10 秒，当前节点拒绝新业务请求，返回 `503 SERVICE_UNAVAILABLE` 和 `Retry-After: 1`，readiness 非 200；已进入执行的请求不强制取消。明确同步错误会提前拒绝，不一定等满 10 秒。配置库失联必须停止接新请求；业务数据源失联则按数据源隔离。

这是可恢复的最终一致性，不承诺零传播窗口、发布零中断、跨节点强一致停用或 exactly-once。需要立即阻断访问时先在入口封禁/摘流并等待在途请求结束。脚本可能写数据，网关/LB 不得盲目重试已发送的 POST。

## 恢复和观测

- `DEPLOYING` 恢复发布，`REMOVING`/`REMOVE_FAILED` 恢复注销；沿用既有失败状态及人工重试方式。
- 内部 generation 递增并校验完成/失败回写，阻止旧回调覆盖新状态，不新增对外 revision 协议。
- `GET /internal/v1/runtime` 要求管理 Token：提供当前响应节点的 readiness、加载/目标修订号、最近确认时间、安全错误摘要。LB 可能返回不同节点，**不是全副本聚合列表**；排查访问节点地址。
- 管理接口在未就绪时仍可用，便于修正坏配置。未就绪节点不能靠端口存活判定为可接业务。

## 容量边界

每节点、每业务数据源都有独立池，当前托管 JDBC 池最大 10、最小空闲 0。N 台可占用约 N × 数据源数 × 10 条业务连接，另加配置库池；扩容必须核对数据库容量。

本方案修复副本一致性、减少请求路径配置查询，不会自动消除慢 SQL、脚本执行/日志开销或大结果集成本。生产容量仍需真实 SQL、数据量、网络、脚本和治理策略下的长时间压力测试，本机短测不是额定容量认证。
