# 在线 Java 重命名修复验证（2026-09-26）

范围：文件栏入口类重命名、源码定位与语言服务托管文件同步。没有新增依赖、服务或接口，没有改变保存、编译、运行规则。

## 复现与原因

1. 在既有开发环境（UI 8887、Admin 8080、TaskEngine 8091/8191）使用真实 Monaco 和 JDT LS 复现截图错误。CRLF 源码中，Monaco 对空行返回空 token 数组；前端从 token 重建文本时丢失空行的 `\r`，后续入口类偏移向前移动。诊断样本期望偏移 84、实际 82；真实重命名请求的零基行列为 `(5,17)`，落在 `class` 关键字，返回 `changes: {}`。LF 对照请求为 `(5,19)`，能正常返回修改。不是用户新类名错误。
2. 扩展回归发现连续改名、撤销、复用旧名称时，JDT 返回 `Compilation unit 'FirstJob.java' already exists`。TaskEngine 删除旧物理文件但未通知 JDT 更新资源记录。新增真实语言服务回归在修复前失败，修复后通过。

## 修复

- 前端按原源码长度屏蔽注释/字符串，不从 token 拼接正文，保留 CRLF、混合换行及 UTF-16 偏移。
- 确认改名时再次校验入口类存在；没有修改结果时不再直接归因于用户源码错误。成功提示不与自动保存开关冲突。
- 托管文件路径变化后，由 TaskEngine 发送旧文件删除、新文件创建通知；仍限于当前会话受控路径，不接受浏览器任意文件操作。
