# 文件数据集功能与压测记录（2026-09-24）

状态：本轮有界专项验证完成；49 组功能/API 用例通过，1 组因缺少计算引擎未执行。
适用于本次工作树，不代表已提交、已发布生产版本或生产容量认证。

## 测试范围与判定方法

本次在真实开发 PostgreSQL、102 服务器 MinIO 上进行文件数据集功能、并发、故障恢复及清理验证。
使用两个专用 Admin；测试期间关闭旧 IDE Admin，避免旧 Worker 混入修复后的回归。
原始样本不修改。测试对象独立命名、按 UUID 清单清理；失败现场先保留日志和状态证据，再清理数据。

除 Job 的 SUCCEEDED 状态外，同时校验逻辑表数量、完整行数、当前来源、装载锁、实际预览，
正常文件另外校验下载 SHA-256。负例要求拒绝且不污染现有来源；故障测试要求旧 Worker 恢复后仍可读。
租约过期时旧、新尝试可能在物理执行上重叠；本次验证有效结果提交与存储隔离，不验证物理执行 Exactly Once。

## 测试环境与资源边界

- VM：192.168.5.102，约 32 GiB 内存，根文件系统 61,188,603,904 字节；数据库和其他中间件不停止、不清空。
- 初始根盘可用 35,634,348,032 字节；清理上一轮后、持续测试前可用 37,813,538,816 字节。
- PostgreSQL 使用已有开发数据库；MinIO 使用已有 bucket，已验证未启用版本管理和 Object Lock。
- 两个 Admin 通过根 `start-local-dev.sh` 的临时测试入口启动，local Profile、同一配置/数据库/MinIO，
  `ddl-auto=validate`、每实例 2 个 Worker、每实例最大堆 3 GiB；私有临时目录；不改变租约和重试参数。
- 8080 原 IDE 实例在队列空闲后停止；测试结束通过统一启动脚本恢复。
- 持续测试每批 4 文件，轮换 14 格式；每批完成验证即删除，批次最小间隔 30 秒，不无限累积。
  根盘可用空间低于 10 GiB 或清理后出现新增对象残留即停止加压。

本次测试在开发环境执行，未进行生产环境容量测试或 7×24 小时持续运行测试。
Admin 运行在本机，文件对象位于 VM；不能把本次吞吐和内存数据直接当作所有服务同机部署在 32 GiB VM 时的容量结论。

| 并发操作 | 6 路同时追加的接受/冲突结果及最终行数一致；上传后删除与后台领取/解析竞争，无意外 500 |
| 租约与物化 | GDB/SHP 暂停专用进程，实际等候租约过期和退避，由另一实例接管；恢复旧进程后再验证行数及预览 |

测试程序最初对 Search DSL 和整文件替换 HTTP 状态的预期有误，已修正并重跑；这些属于测试工具问题，
不计作产品缺陷。原样本 WKT 没有明确 EPSG authority，允许更改回退 EPSG 是设计行为，不是 CRS 校验失效。

## 已发现并修复的缺陷与优化

| 项目 | 修复前 | 本次处理 | 验证结果与依据 |
| --- | --- | --- | --- |
| 旧 Worker 清理覆盖新物化对象（前轮） | Job 显示成功，恢复旧 Worker 后 GDB/SHP 实际预览失败 | Job 的每个 attempt 使用独立兄弟前缀，旧尝试只清理自身目录 | 前轮复现；本轮两格式暂停接管恢复回归及正规单元测试 |
| 删除与解析死锁 | `cancelQueuedAndLockTables` 与 Worker 的表/文件/Job 锁反向等待，真实请求返回 500 | 业务变更与 Worker 状态提交以数据集锁协调；领取/恢复同时跳过已锁定 dataset 和 job；不把解析 I/O 放入事务 | 原始 PostgreSQL 死锁日志；修复后并发删除 API 回归及锁顺序单元测试 |
| 同来源领取快照窗口 | 单条 SQL 的 NOT EXISTS 无法单独保证跨事务的最新状态 | 持有数据集锁后用新语句复查同来源 RUNNING Job，再领取 | 单元测试及多图层/持续负载执行记录 |
| 多 Admin 权限初始化竞争 | 两实例删除重建同一角色授权，出现行数不匹配导致启动失败 | 权限初始化事务在任何读取前取得 PostgreSQL SHARE ROW EXCLUSIVE 表锁，提交/回滚自动释放 | 锁顺序/失败回滚单元测试；两个专用 Admin 同时发起启动并均 readiness=UP |
| GEOJSONL RS 提示/识别 | Java 空白判断吞掉 RS，错误分类不准确，已有自动化断言失败 | 在空白判断前检测 RS，包含仅 RS 的行及样本后的非法行 | 修复前 53 项中 1 项失败；修复后单元和 API 负例通过 |
| EPSG 确认字段重建冲突 | GDB/SHP 确认原 EPSG 就触发字段名唯一约束，返回 409 | 同一事务先删除并 flush 旧字段，再插入新 Schema；失败保持事务回滚 | 两格式真实 API 复现；新增字段操作顺序/行数保持单元测试及 API 回归 |

未新增生产依赖、数据库表或公共接口。上述变化不迁移历史物化结果，不重置用户权限配置，
也不把源坐标声明变成坐标转换。锁定规则升级应覆盖所有参与同一队列的 Admin。

## 清理与证据

- 30 分钟有界负载不能替代小时/天级浸泡及容量极限测试；工作集升高本身不能判断内存泄漏，需要结合堆和 GC 趋势。
- XLSX 样本通过；未覆盖所有 XLS、Excel 公式/合并单元格/特殊日期及所有 GIS 变体；GDB 总数是索引计数，未校验抽样窗口外每条二进制记录。
- 强制杀进程可能遗留未发布物化目录；本轮不引入自动全 bucket 清理。运维只能按对象引用与具体任务证据清理孤儿，不能按宽泛目录删除。

## 测试结论

在上述样本、并发度和运行时长下，49 组功能/API 用例通过，持续负载与集中并发共 382 个 Job 成功，
GDB/SHP 暂停接管恢复回归通过。修复后并发删除未再观察到 500，两个专用 Admin 同时启动均达到就绪状态。
本次结果仅覆盖记录的测试条件；计算引擎/Canvas 联调、长期稳定性、容量极限及依赖故障场景尚未验证。
