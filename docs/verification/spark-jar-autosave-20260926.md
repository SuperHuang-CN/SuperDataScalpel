# 在线 Java 草稿自动保存验证（2026-09-26）

范围：在线批流 JAR 共用工作台；仅前端改动，复用已有草稿保存接口。设计见 [SDK 与在线开发](../design/spark-jar-task-sdk-v1.md)。

## 实现

- 默认开启，当前浏览器记住开关；停止输入 1.5 秒后保存，关闭后显示手动保存按钮，取消尚未提交的自动保存。
- 不因打开页面而保存默认模板，不触发编译、试运行或应用；保存成功只更新状态，失败直接显示失败和重试入口。
- 同一页面串行保存，旧响应不覆盖新编辑内容；后续修改继续保存。换行符规范化不触发重复保存。超出 256 KiB 不发送请求。
- 保留未保存/保存中的刷新与离开提醒；切换任务以任务 ID 隔离组件状态。多人版本冲突不在本次范围。

## 验证结果

- 页面测试覆盖默认开启、无编辑不请求、输入防抖、关闭取消排队、手动保存、偏好记忆、保存中继续输入、失败暂停/重试、重新开启、卸载取消、大小限制及换行符处理；同时保留原检查/资源编辑用例。
- TypeScript 与两个修改文件 ESLint 通过。jsdom 仍有既有 CSS 解析提示，不影响断言。
- 在既有 UI 8887 / Admin 8080 上，使用专用自测任务 `cd2cb624-074a-4c00-8a0a-4280d8e0cf83` 验证真实保存接口：默认自动保存、刷新回读、手动模式不自动请求、点击手动保存、网络失败后保留源码、停止自动重试、点击重试成功，均通过。记录到的源码操作仅为 save，没有 check/compile/trial 请求。
- 浏览器端仅对本次测试的语言连接申请注入失败，主动进入无语义提示编辑，以独立验证保存流程，不改变后台配置、不创建 Mock 应用；保存接口请求真实到达 Admin。保存失败用浏览器单请求网络失败注入，不影响其他用户。
- 1920×1080 页面检查开关与已有操作同栏，自动模式不显示手动保存按钮。测试源码最终经真实接口恢复，源码 SHA 与原已编译 SHA 精确一致，当前 JAR 与编译摘要保持不变。自动化输入改用真实剪贴板粘贴，避免多行逐键输入触发 Monaco 自动缩进；中断测试残留恢复前已通过原编译摘要验证，不根据猜测覆盖源码。
