# Java 语义提示重连修复（2026-09-26）

## 问题与范围

Admin 每 15 分钟要求重新鉴权。此前前端只在普通分析请求完成时重置重试次数，重连准备完成却不重置；不继续触发补全的用户在累计第三次断线后会停止自动恢复。另有失败准备尚未退出、重试定时器已触发而被 `connecting` 丢弃的时序缺口。

本次只修改前端语义连接生命周期及安全错误提示，不修改任务源码、草稿保存、SDK 方法或正式执行。

## 修复

- 类型探测和当前文档分析全部成功后重置连续失败计数；仅握手成功不重置。
- 连续失败最多自动重试三次，仍可手动重试；退出页面取消重试。
- 等失败准备退出后再安排重试，旧连接的异步异常不覆盖已经报告的失败原因。
- 按关闭码、进程状态及失败阶段显示安全原因；不展示任意底层异常或内部路径。

## 验证

- 语义适配、WebSocket 连接及准备流程共 37 项单测通过，包含五轮成功后断线、连续失败限流、准备中断线、销毁清理和安全关闭原因。
- 扩展至入口解析、语义重命名及在线编辑页回归，共 6 个文件 60 项测试通过；测试环境输出原有 CSS 解析警告，无测试失败。
- TypeScript 构建检查与四个修改文件的 ESLint 通过。
- 用户现有 UI 8887 → Admin 8080 → TaskEngine 8091/8191 环境，独立浏览器只读打开原任务，拦截源码写入；连续五次主动断开该测试浏览器自己的语义连接，五次均自动恢复就绪，恢复约 2.9 秒（含 2 秒重试间隔），未触发用户补全请求。旧实现同样测试第三次无法恢复。
- 测试使用主动关闭模拟断线，不是等待五轮真实 15 分钟鉴权周期；未重启服务，也未验证集群或负载容量。
- 本次前端修改刷新页面生效，无需重启 Admin 或 TaskEngine。
