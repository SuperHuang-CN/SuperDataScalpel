## 顶级管理页视觉语言

- 共享表格与控件统一使用湖蓝设计基线，优先于下文遗留的蓝紫装饰描述：`workspaceResourceTheme` 为 Ant Design 根主题、应用外壳及资源覆盖层共同的字体、链接色与主色来源，CSS 使用 `--ds-ui-font`、`--ds-primary` 和表格颜色变量。普通中文、编码及物理表名使用同一无衬线字体；SQL 和代码编辑区域保留专用代码字体。
- 全部页面的普通表格表头统一使用低饱和浅灰蓝实色底 `#dce7ee`、深蓝文字 `#274b60`，排序／悬停底色 `#d0e0e9`、分隔色 `#c2d3de`，与浅色工具栏和白色表体拉开层次。CSS 与 Ant Design Table 主题均引用共享表头变量，覆盖数据资源、数据建模及其他模块的列表、详情、导入预览与弹框表格；表头两端统一直角，外层面板使用共享小圆角，专业编辑器密度保持不变；悬停为 `#f0f7fa`，链接为 `#287f9e`，结果栏白底、细分隔线；禁止在共享详情规则中强制覆盖为紫色背景。筛选控件统一 36px 高、4px 圆角，结果栏分页与刷新采用 32px 紧凑尺寸。焦点、Hover、排序态与主色一致，取消查询按钮的彩色投影及悬停位移；危险操作和任务状态继续保留语义色。
- 顶级管理页采用克制的蓝紫未来感：应用工作区使用淡蓝至淡紫渐变，主侧栏使用深钴蓝至靛蓝渐变；不得引入大型纯装饰 3D 元素占用数据空间。
- 查询面板、目录面板和结果面板使用半透明白色材质、低对比度边框、柔和阴影与适量背景模糊建立层级。浏览器不支持背景模糊时必须回退为不透明白色，不能影响可读性。
- Panel 阴影统一分为三档：页面级查询、目录、结果、详情身份头和完整工作台使用标准阴影；详情信息分区、抽屉内部纸面和局部卡片使用更弱的内部阴影；Popover、Modal 等真实浮层才使用高层阴影。普通业务页面不得自行增加新的阴影参数组合。
- 相邻且连续的结果工具栏、表格、分页，以及 Drawer 的正文和底部操作栏不得分别投影；只允许最外层 Panel 投影，内部关系使用 `1px` 分隔线和背景层级表达。禁止使用大幅向下偏移的阴影形成横向灰色或紫色带。
- 查询面板与结果面板相互独立；结果工具栏、表格和分页必须保持为一个整体。不得在结果面板内部继续堆叠无业务意义的玻璃 Card。
- 全站使用小圆角：状态标签约 3px，普通控件、菜单选中项与资源图标块约 4px，外层面板、卡片、Modal 和 Drawer 约 6px；通过 `--ds-radius-tag`、`--ds-radius-control`、`--ds-radius-panel` 及 `workspaceResourceTheme` 统一。现有直角衔接保持直角；头像、状态点、图表点、开关与连接端口等圆形语义元素保持原有几何形状，不对所有元素强制同一圆角。
- 普通资源列表的主身份列使用 32～36px 的低饱和单色图标块辅助识别；调用排行、异常明细等统计表保持紧凑并省略资源图标。状态使用语义明确的轻量圆角徽标，不得只靠颜色表达含义。`ManagementStatusIndicator` 统一为 24px 最小高度、左右 8px／上下 1px 内边距、20px 行高、1px 语义色边框与 3px 圆角；状态点与文字间距 6px，保留浅底深字。页面不得清零其内边距或边框，也不得单独恢复胶囊圆角。
- 统一视觉通过明确页面作用域覆盖顶级管理页、业务详情页、数据服务全页编辑器、首页、登录页和非 Canvas 业务覆盖层；各作用域只能共享视觉变量和窄职责 CSS 契约，不得用无边界全局选择器重写其他页面。
- 动效限于短时颜色、阴影和轻微位移过渡；必须尊重 `prefers-reduced-motion`。文字、键盘焦点和状态颜色需要满足可辨识性要求。
- 视觉升级不得破坏 1920×1080、100% 缩放下无页面横向滚动的目标，也不得改变双行语义合并、显式查询、固定表头与分页等交互规范。

## 详情页视觉

- 文件数据集、码表、模型、任务和数据服务等业务详情统一使用“玻璃身份头 + 完整页签内容面板”。身份头约 72px，使用半透明白色、6px 圆角、柔和阴影和适量背景模糊；不得再增加独立大标题或无业务意义的指标卡。
- 身份头左侧依次为返回入口、40px 低饱和资源图标块、名称、编码、状态和辅助信息；右侧保留刷新、修改、生命周期操作及更多菜单。最多一个主业务操作使用蓝紫渐变，长名称、多状态和多操作时必须允许合理收缩或换行，不能造成页面横向滚动。
- 页签导航约 48px，使用淡蓝紫选中背景和渐变强调线；页签内容是一个完整面板。完整详情页中的静态属性、配置、运行摘要和业务说明必须使用独立信息分区面板：6px 圆角、低对比度蓝紫边框、柔和阴影以及约 52～56px 的标题栏。左侧 3px 蓝紫渐变强调线只能位于标题栏内，不得贯穿正文内容。每个分区必须提供 36px 低饱和蓝紫图标块、明确标题和一句简短辅助说明，不得只放孤立的加粗标题。
- 同一详情页及全局详情信息分区统一使用同一套蓝紫强调线、图标块、边框和面板背景，不得用蓝、紫、青、橙等任意颜色区分业务分区。语义色只用于真实的成功、警告、错误、处理中等状态反馈，不能作为分区装饰色。
- 详情信息分区的静态属性统一使用共享信息网格：每个字段是独立的“弱标签 / 强内容”语义单元，标签约 12px 蓝灰色并直接位于约 14px 深色内容上方。不得使用 `bordered Descriptions` 形成整行标签色带、标签行与内容行分离的传统表格结构，也不得通过条纹背景模拟表头。宽屏基础标识默认四列，连接、运行和资源配置默认三列，中等窗口降为两列，小窗口降为单列；长说明、错误摘要和物理地址应合理跨列，普通末尾字段不得被组件自动拉伸为整行。
- 分区关系通过间距、边框、标题层级和柔和阴影建立，不得堆叠厚重描边、多层玻璃 Card 或大面积渐变。表格、代码块、状态反馈和 Empty 可以作为分区内容，但不得再包一层无业务意义的 Card；表格、代码编辑器、Canvas、抽屉和弹窗按自身密度单独处理，不得机械套用详情信息分区。
- 完整详情页的页签内容与信息分区使用统一空间节奏：页签栏到首个分区 `12px`，分区左右内缩 `12px`，相邻分区间距 `12px`，最后一个分区到页签容器底部 `16px`。该留白必须由共享页签内容层统一提供，各业务页面不得重复声明或叠加 padding；Canvas、任务定义编辑器和其他专业工作区保持零留白或使用自身独立契约。
- 详情页内带分页的关联列表、运行记录和日志表格使用顶部紧凑结果栏：左侧显示列表名称和总数，右侧将必要业务操作与“每页条数、简洁页码、刷新”分页控制分组展示；表格不得再占用独立底部分页行。无法提供总数的顺序分页也必须在顶部显示当前页、上一页和下一页，不得保留自定义底部分页。筛选条件留在左侧，查询和重置固定在筛选工具栏最右侧；该规则只适用于详情页嵌入式表格，顶级管理列表继续使用固定底部分页。
- 详情页嵌入式表格的筛选区统一使用约 `54px` 高的独立淡蓝紫半透明工具带，具有 `12～14px` 圆角、低对比度边框和极轻阴影；与结果区域保持约 `12px` 间距。筛选项不得保留“名称、状态、模式”等外置 `Form.Item` 标签：主搜索框使用搜索图标和具体的名称/编码占位文案，枚举控件使用“全部状态、全部类型”等自解释占位文案。查询使用克制的蓝紫渐变主按钮，重置使用低干扰文字按钮，两者固定在最右侧；刷新和分页属于结果栏，不得混入筛选操作。窄窗口允许工具带内部换行，但不得造成页面横向滚动。
- 任务详情只统一外层身份头、页签和普通内容；Canvas 定义编辑器、画布、节点面板和 Canvas 内部组件必须保持独立视觉边界，后续单独设计。

## 业务 Drawer、Modal 与表单

- 所有非 Canvas 业务 Drawer 和 Modal 必须增加统一 portal 作用域 class。共享样式只能通过该 class 生效，不得全局覆盖所有 Ant Design 覆盖层；Canvas 与任务编排覆盖层明确排除。
- Drawer 应先按业务复杂度选择结构，不得机械套用同一个大表单：单一配置或少量字段使用约 560～680px 的轻量纸面；普通资源使用约 680～820px、1～3 个明确业务分区；包含大量条件分支、连接参数或运行策略的复杂对象使用约 920～1120px 工作台，确有连续步骤时才增加左侧步骤导航；以筛选和批量勾选为核心的登记类操作应让表格成为主要工作区。不得为了显得“高级”给简单对象增加空步骤、无意义导航或大面积留白。
- Drawer 使用轻靛蓝遮罩、约 2px 背景模糊、淡蓝紫玻璃标题栏、白色主体和固定白色底部操作栏；右侧抽屉使用 16～18px 左侧圆角和柔和左侧阴影。标题栏左侧必须是与资源语义一致的图标块，旁边依次放主标题和一句短说明；状态、类型或模式放在标题栏右侧，不能让图标漂到标题右侧或把多个普通字段塞进标题栏。
- Modal 使用 16px 圆角、淡蓝紫标题区、清晰白色主体和带分隔线的底部操作区。危险确认继续使用红色语义、明确资源名称和二次确认，不得因为视觉统一弱化危险提示。
- 表单控件使用 8px 圆角、清晰边框和蓝紫焦点环；主按钮可使用蓝紫渐变，次要按钮保持浅色。长表单沿用现有分区与两列布局，分区使用白色纸面或淡紫辅助背景，不堆叠多层玻璃 Card。每个分区必须按业务任务命名并配合短说明，字段顺序应遵循“身份 → 业务配置 → 高级/保护配置”，不得按 DTO 字段顺序机械排列。
- 启用、推荐、注册等影响整个分区的布尔状态优先放在对应分区标题栏右侧，与普通输入字段分离；仅影响单个字段的开关仍留在字段上下文内。状态位置必须固定，不能因新增态、修改态或条件分支造成标题和输入列抖动。
- 底部操作栏左侧显示当前对象、选择数量、配置模式或保存后的后续动作等紧凑业务上下文，右侧保持“取消 + 唯一主操作”；不得在底栏并排堆积多个同级主按钮。异步操作继续保留 loading 和防重复提交。
- API Key、Token 等可选凭据优先使用“未配置 / 已保存”的直接状态和“配置 / 替换”操作按需展开输入框，避免密码管理器在抽屉打开时误填普通字段。该交互不得使用隐藏诱饵输入、随机字段名、焦点后解除只读等欺骗方案；展开后的凭据字段仍须遵守本文件的自动填充与 DOM 命名约定。
- 尚未按业务重新设计的复杂业务 Drawer 采用“清透精密玻璃工作台”作为基准：标题区必须具备资源图标、主标题、辅助说明和紧凑状态；左侧使用带编号与连接关系的浅色步骤导航；右侧分区采用统一白色玻璃纸面、低对比度蓝紫边框、柔和双层阴影和图标标题栏。此类复杂配置抽屉的输入控件可在自身作用域内使用约 `40px` 舒适高度，不得修改全局组件尺寸。用途或模式等少量互斥/多选项可使用低饱和图标选择卡，底部操作栏保持半透明且固定可见。上述装饰统一使用蓝紫中性色，语义色仅用于真实状态，不得为不同分区随意更换装饰色。
- 视觉调整不得改变 Drawer/Modal 尺寸、字段、校验、权限、loading、确认、提交行为和嵌套业务流程；复杂抽屉只调整外壳、分区、导航和表格视觉。

## 全页编辑器、首页与登录

- 客户资产门户独立于管理应用外壳，按[客户资产门户设计](../design/asset-portal-customer-design.md)使用湖蓝浅色页面、城市主视觉、领域导航、精选与最近发布、分页目录及详情。此范围使用正常页面滚动和 URL 查询条件，轮播支持暂停与减少动态效果；管理表格的固定内部滚动、工作区面板及旧装饰规则不套用于客户门户。

- 数据服务新增和编辑路由由应用外壳提供专用全高工作区，不得依赖负 margin 抵消页面边距。顶部使用圆角玻璃身份栏；标准服务表单放在居中的白色编辑面板，SQL 和脚本服务保持左侧约 340～360px 配置面板与右侧大型定义面板。
- Monaco、SQL 编辑器和脚本工作台的内部主题与交互不得由全局视觉样式改写，只统一外层容器、边框、圆角、阴影和分区导航。
- 首页使用湖蓝强调色、雾蓝工作区和深海蓝灰导航，保留连续地图与底部资源入口。上方三栏展示模型建设、任务生产、服务交付；下方用“服务调用 / 任务执行”两个实际切换的分析视图分别展示指标和趋势；右侧展示待处理告警、数据质量。固定正文字号 14px、辅助统计标签 13px、分区标题 16px，不随大屏放大。1100px 宽、680px 高及以上按工作区剩余高度布局；1366×768 等笔记本不累计堆叠两张趋势图。模型分层以横向条形图分页显示，每页6项，使用全量分类统一比例尺；更小窗口正常纵向重排，不裁掉统计。
- 首页不设置与正文重复的“概览”标签页，仅下方两种分析切换内容。模型、任务、服务、调用、执行、告警、质量七个模块完整保留。分类概览按语义采用不同图表：模型分层使用分页横向条形图，任务类型使用环形占比图并保留分类数量与运行摘要，已启用服务使用纵向柱状图比较类型数量，柱内红色部分标明其中的部署异常。环形图零值分类保留图例，全零时显示中性空环，不伪造占比；柱状图零值保留标签与数值，全部类型使用同一比例尺。图形与图例支持悬停、键盘聚焦和列表跳转；自定义分层增删通过分页适配，避免固定高度裁剪末行。服务调用主指标为调用总量、HTTP成功率、平均响应耗时和5xx错误；原成功调用次数、调用服务数和调用方数移至辅助信息。图表时间段可通过悬停、聚焦和点击查看具体数值。任务汇总有值但趋势不一致时，显示真实结果分布与重试入口，不显示空数据。查询均维持在父页面，不因切换分析视图丢失时间窗口或停止刷新；按账号权限显示视图。统计口径和更新时间通过各自 ContextHelp 支持悬停、点击、键盘访问，告警与加载错误始终直接展示。查看运行记录、调用分析、质量明细抽屉与各筛选跳转不变；复用现有接口、不伪造数据。
- 共享导航底部保留低对比度等高线纹理，工作区使用一张表现地形、空间图层配准与时间采样轨迹的连续插画，仅作装饰且不拦截交互，不表示真实监测数据。导航展开时底部保留“空间数据 / 让数据创造更大价值”，与可滚动菜单分开；收起后隐藏说明。右下角不显示“设计概念”等样稿署名。
- 常规桌面左侧白色工作区与右侧告警质量区域占满可用高度，资源入口留在左面板底端；告警过多时仅告警列表内部滚动。复杂错误与额外长内容允许局部滚动，更小窗口恢复自然页面滚动，不使用 overflow:hidden 掩盖指标或缩放整页。
- 共享外壳在工具栏与正文的共同容器 `.app-main` 内使用单个装饰图层 `.app-workspace-backdrop`，通过 Vite 导入本地 `workspace-spatiotemporal-background.png`。插画上方集中表现完整的微缩河谷、叠置空间图层及时间采样轨迹，下方延续为低对比度等高线与地块纹理；不再叠加另一张地图或独立顶部横幅，避免地理主体重复与拼接。图片通过 object-fit:cover 等比覆盖工作区并保持顶部对齐，左侧文字区域叠加局部雾蓝遮罩，窄屏降低装饰对比度；装饰设置 aria-hidden、禁止拖动且不拦截指针，不改变内容高度。所有后台页面共用这一背景，顶部工具栏使用透明底。首页的标题与统计布局由 `app-shell-home` 隔离。所有后台路由共用 AppShell 的侧栏和顶部导航，展开侧栏统一 220px；导航、工具按钮及菜单弹层通过局部 ConfigProvider 统一使用 `"Segoe UI", "Microsoft YaHei UI", sans-serif` 和湖蓝主题，切换页面保持一致。普通管理页工作区透出共享地图，查询栏使用不透明雾蓝白底与湖蓝按钮、焦点边框，保证控件清晰可读；普通列表与详情页顶部透明背景区为 88px，导航与右上工具组仍靠顶部，不随背景区增高而居中下移；工作区内边距为 12px，横纵面板间距统一为 9px，筛选工具带上下内边距 8px、最小高度 54px。窗口高度不超过 760px 时背景区收至 72px，宽度不超过 900px 时使用原有紧凑换行布局。首页及专业编辑器保持原有高度。业务表格、Canvas 与编辑器继续使用原有主题作用域。菜单结构、稳定 URL、展开收起偏好、顶部资产门户、AI 助手、通知和退出行为不变。
- 共享顶部右上操作入口使用有浅色边框、74% 不透明度的浅色工具组，桌面上边距 10px，避免文字直接叠在地图纹理上。资产门户为描边按钮，AI 助手为湖蓝实色按钮，通知保留未读提示并增加文字标签；用户名与部署信息组成账户区，退出保持独立操作。按钮固定 32px 高、14px 字号，工具组上下内边距 4px、左右 10px、入口间距 8px，账户两行信息行高分别为 18px 与 14px；桌面工具组约 42px 高、靠顶部对齐，保持页头原有高度以露出下方背景。窄窗口自然换行，不随大屏放大；工具区样式在所有后台路由保持一致，原入口、权限和业务行为不变。
- 登录页使用冷灰蓝背景、湖蓝强调色和白色表单面板；桌面双栏呈现平台介绍、本地时空数据治理主视觉与登录表单，900px 及以下收为单栏并隐藏装饰插画和流程。登录插画使用透明素材 `login-spatiotemporal-cutout.png`：左侧表达影像、点位与矢量数据接入，中间以地形、配准空间图层和时间采样轨迹表达建模与处理，右侧表达服务输出；与下方真实流程入口对应。插画使用 contain 完整展示，使用真实透明背景与页面融合，不用 multiply 混合模式叠出矩形底色，不裁切输入输出图层，不复用工作区的窄幅顶部构图；图片不带烘焙文字，不代表实际业务数据。登录页整体内容组垂直居中，最大宽度 1440px；品牌与主内容间距固定，左右内容顶对齐，平台标题与表单标题使用相同顶部内距。桌面表单宽 440px，1100px 及以下为 380px，保持正常阅读和输入尺度；正文与表单为 16px，不随大屏持续放大，底部流程使用业务图标与清晰名称。插画高度按视口扣除 400px 文字及布局预算，上下限为 160px 和 440px；不按屏幕宽度持续放大。桌面窗口高度不超过 850px 时收紧页边距、表单间距及按钮高度，保留正常字号和全部内容；不使用 overflow:hidden 遮蔽超出内容，极矮窗口及表单错误撑高时允许自然滚动。不连接外部服务、不表示实时业务数据。字体限定在登录页，采用 `"Segoe UI", "Microsoft YaHei UI", sans-serif`，通过局部 Ant Design ConfigProvider 同步到控件；保留浏览器自动填充、测试账号提示和认证行为，不使用高干扰动效。

<a id="app-shell"></a>

## 应用外壳与全局菜单

- 模块公开入口中的空间预览和血缘图组件按实际渲染懒加载，并在组件边界显示加载状态；首页统计和普通资源列表引用模型 Hook 时，不应连带加载 MapLibre 或 X6。普通数据源列表沿用全局查询缓存有效期，只有按已发布模型筛选的资源选择器保留每次挂载强制刷新的语义，避免切页反复进入加载态。
- 顶部栏承载侧栏开关、面包屑、部署信息和用户操作。普通列表的筛选工具带直接位于顶部栏下方。
- 主菜单导航通过 React Transition 跟踪页面提交：点击后在主工作区顶部显示 3px 不定进度条，目标菜单项高亮并显示小型加载图标，正文标记忙碌状态；面包屑不追加加载文字。懒加载未完成时即使保留旧页面，也不能没有反馈；加载反馈不挤动布局，不遮挡操作，不伪造百分比，随实际过渡结束消失，连续选择其他菜单仍可导航。减少动态效果偏好下保留静态状态指示。
- 侧栏按“资源接入 → 数据建模 → 任务开发 → 服务开放 → 资产治理 → 运行运维”的工作流组织，并将低频平台设置集中在底部系统管理。现行分组如下：

| 一级入口 | 二级菜单 |
| --- | --- |
| 工作台 | 首页 |
| 数据资源 | 数据源、文件数据集、全景影像、数据填报 |
| 数据建模 | 数据模型、指标管理、码表管理、字段模板、数仓分层 |
| 任务开发 | 批处理任务、实时任务、工作流、质检任务、脱敏规则 |
| 服务开放 | 数据服务、API 消费者、API 调用统计、MCP 服务、MCP 访问凭证、MCP 调用日志 |
| 数据资产 | 资产管理、业务领域 |
| 运维中心 | 运行监控、告警中心、告警配置、计算引擎、服务引擎 |
| 系统管理 | 用户管理、角色管理、权限管理、系统配置、平台 MCP 接入 |

- 资产门户是独立的发现与消费入口，从顶部栏快捷按钮以 `noopener,noreferrer` 在新窗口打开，不混入后台管理侧栏。同一浏览器、同源的管理页和门户共享登录，直接新建标签访问也能恢复有效会话；不把令牌写入 URL，不依赖 `opener` 传递身份。有效期、跨标签退出与旧版会话迁移遵循 [系统访问管理](../design/system-access-management.md#前端)。匿名独立访问仍可浏览公开资产。菜单按现有权限过滤；分组变化不改变稳定 URL 或权限编码。
- 展开的二级菜单使用内嵌圆角分组面板：与侧栏边缘保留约 6～8px 间距，使用低对比度半透明深蓝背景、6px 圆角和极淡描边，不得形成大面积近黑色块。主菜单与目录统一采用蓝紫高亮、4px 圆角、600 字重及左侧标记的选中结构，配色按深浅背景适配：深色侧栏使用 `--ds-sidebar-selected-*` 的柔和蓝紫底色和浅色文字、图标，不直接铺设目录的浅色底块；左侧浅蓝标记宽 4px、内收 6px、上下留白 9px，避免与圆角粘连，不增加发光或厚重描边。浅色目录继续使用 `--ds-directory-selected-*`。一级入口、二级菜单及侧栏收起后的弹出菜单保持一致，Hover 不覆盖选中态；侧栏全高外轮廓保持直边。

平台 MCP 接入页将三个页签与系统开关、接入地址、目录状态合并在约 52px 高的顶部工具栏中：左侧使用淡蓝紫分段页签，右侧使用紧凑配置控件，不单独设置总开关卡片。开关仍随接口配置统一保存，变更后就近标示“待保存”；目录异常保持可见，窄屏允许顶部工具栏换行。此页样式限定在 `system-mcp-page`，不覆盖其他页面的 Tabs。

平台 MCP 接口表格采用“三行分层”方案，将主要内容合并为“接口信息”列：第一行是可点击名称，第二行是描述，第三行是请求方法标记、操作性质和等宽路径；分类由左侧导航表达。不再单设请求或性质列，只保留可用状态、开放开关两个窄列。名称、描述和请求路径均保持单行，超长显示省略号，并通过 Tooltip 查看完整内容；详情抽屉同步展示完整描述。本表按三行内容自然撑开到约 72～76px，不套用普通双行密度，也不因描述较长而继续增加行高。

<a id="task-center-views"></a>

### 任务开发分组

任务开发按业务场景提供四类入口，共用任务模块、API、权限及 `TASK` 目录。

| 菜单 | 路由 | 包含类型 |
| --- | --- | --- |
| 批处理任务 | `/task/batch` | 本地 SQL、Spark 编排、Spark JAR |
| 实时任务 | `/task/streaming` | Spark 实时编排、Spark 实时 JAR |
| 工作流 | `/task/workflows` | 工作流 |
| 质检任务 | `/task/quality` | Spark 模型质检 |

- 侧栏按表格顺序排列，后接脱敏规则。`/task` 保留全部任务，通过列表结果工具栏的视图切换入口访问；全部任务不高亮任何分类菜单。运行监控与告警保持统一。
- 各分类复用任务列表、抽屉和查询能力，固定类型范围始终与用户筛选条件 AND。切换分类重置筛选、目录选择和分页；清空筛选不清除分类范围。多类型页面提供组内执行方式筛选，工作流和质检隐藏单一类型筛选。
- 批处理新建默认本地 SQL，实时任务默认 Spark 实时编排，工作流与质检固定类型。编辑已有任务不能更改类型。新建时沿用当前目录；共享目录变更影响所有分类。分类页面隐藏跨类型目录资源计数，全部任务保留计数。
- 列表展示发布状态及类型对应的定义摘要，工作流不展示输出模型。快捷操作为定义、运行记录或实时运行；定时计划、立即运行及生命周期等操作放入“更多”。运行状态、工作流进度和质检结论在已有详情页中查看，列表不逐行查询运行信息。
- 详情及编辑器保持原任务 URL，可选 `taskView=all|batch|streaming|workflows|quality` 记录来源。同一任务内跳转保留来源和现有页签、运行参数，返回入口、面包屑及菜单高亮使用同一解析规则；缺失或不匹配的来源按实际任务类型归组，任务不可加载时返回全部任务。跨任务跳转按目标类型归组，保留父子运行关联。

## 查询栏

- 查询区使用单行筛选工具带，不再单独设置“筛选条件”标题。不得为了展示全部条件无限增高筛选区。
- 页面级交互使用标准尺寸而不是全局小尺寸：顶级列表筛选控件、结果工具栏主要操作、详情头部操作、业务 Drawer/Modal 表单与底部操作、非 Canvas 全页编辑器表单统一为 `32px` 高、`14px` 字号。主要搜索框在宽屏下约 `300～320px`；筛选工具带最小高度约 `60px`、控件间距约 `10px`。
- 表格行内操作、分页、目录树操作、Canvas Inspector 和其他高密度编辑器继续使用 `24～28px` 紧凑尺寸。不得通过修改全局 `componentSize` 一起放大；新增页面必须通过明确的页面或业务容器作用域选择标准尺寸，并为其中的 Table、Pagination 和 Canvas 紧凑区保留豁免。
- 顶级列表筛选工具带分为左右两组：左侧依次铺开名称/编码等主搜索框和所有当前可容纳的枚举条件；右侧固定放置“更多筛选、查询、重置”操作组。查询与重置必须贴近工具带最右侧，不能停在条件中间形成大片无意义空白。搜索框使用搜索图标和简洁占位文字。
- 普通输入框、枚举和时间范围只修改查询草稿，不直接请求；点击“查询”统一提交普通条件和已确认的高级条件，搜索框按 Enter 等同于点击查询。所有查询提交均回到第一页，不修改现有服务端查询协议。
- “查询”使用主按钮并固定在工具带右侧操作组。目录树属于导航上下文，选择后可立即刷新，但只能使用已经应用的查询条件，不得静默提交尚未查询的草稿。
- “更多筛选”是空间不足时的响应式降级，不是固定的信息层级。工具带能够单行容纳全部条件时，低频条件也应直接展示且不得出现“更多”；只有容器实际放不下时，才将低优先级条件折叠为“更多 · N”。折叠判断必须依据筛选容器的实际可用宽度，不得只按浏览器宽度或写死某个业务页面。弹层中的“确定”只保存草稿而不请求，“取消”丢弃本次修改，“清空高级条件”清除高级草稿，最终仍由工具带“查询”统一提交。
- “重置”在查询草稿、已应用条件、高级条件或目录任一非默认时展示；重置应清除普通、高级和目录条件并立即恢复默认列表。
- 结果工具栏左侧展示“资源列表名称”和“共 N 项”，右侧按“刷新、辅助操作、主业务操作”排列。刷新使用带 Tooltip 与 `aria-label` 的纯图标按钮，主业务操作使用主按钮，例如“+ 新建数据源”。不得另设重复的页面标题区。

### 数据源列表

### 全景影像与数据填报

- 两页结果标题均带业务图标；刷新及上传／创建与查询位于同一工具带。全景主筛选保留名称与处理状态，位置和拍摄时间收进“更多”；查询、刷新、主操作保持自身宽度，窄屏自然换行，不挤压输入项。列表／地图切换仍在全景结果栏。
- 创建填报表单采用最长 960px 的单选模型表格，仅展示尚未绑定表单的 MANAGED 受管模型，排除逻辑注册模型，不提供无效的模型模式筛选。顶部提供名称／编码、分层和绑定数据源组合筛选，分层与数据源选项也仅来自该候选范围；表格保留名称、编码、分层、数据存储及 Catalog／Schema／物理表、状态／版本和填报适用性。按服务端问题码区分“当前不支持填报”和“发布条件待完善”，完整原因及检查边界就近展开；通过基础检查不等于已验证物理表。使用服务端分页，底栏始终显示已选模型和创建草稿操作，选中有问题模型时明确发布限制；筛选不静默替换选择，受管模型的已知问题不改变创建草稿的资格。

- 两个模块复用 `workspaceResourceTheme`，列表、详情及所有操作抽屉使用 `resource-workspace` 显式作用域：白色面板、湖蓝强调、14px 正文和 36px 标准控件，表头采用浅灰蓝；不使用旧紫色渐变和装饰性嵌套卡片。目录仍按资源域隔离，全景目录复用公共目录完整功能；数据填报按目标模型管理，不新增目录。
- 全景列表保留名称、状态、位置和拍摄时间筛选，以及列表／地图切换；提供直接修改与删除，处理中删除限制不变，失败原因可在状态列查看。上传支持拖放与逐文件状态、重新上传和重试处理；文件规格、并发数、替换单文件限制及版本检查不变。详情保留全景浏览、全部元数据、人工修订、原图下载、替换与放弃替换。
- 数据填报列表名称与详情图标均可进入表单；创建入口保留候选模型及准入问题提示。详情完整保留发布／停用、单条提交、数据查询编辑、批量删除、字段配置、导入和操作日志。批量导入使用单层白色工作区，完整校验、预览、问题行、人工核对与失败信息持续可见，窄屏不隐藏反馈；保留原校验与确认导入流程。
- 删除全景影像和填报表单的确认框沿用资源删除样式，明确对象及删除影响；详情和列表入口共用全景删除确认内容。填报表单删除继续明确说明不会删除物理表数据。所有权限、提交结构、业务校验与状态约束保持不变。

### 文件数据集列表

- 文件数据集详情沿用数据源工作区的湖蓝、白底和统一字体控件，覆盖本域旧蓝紫嵌套卡片样式。概览仅展示基础信息、共享参数和当前表状态；文件页保留最近解析，完整记录在“解析记录”页签按当前数据集筛选、分页和查看完整错误，文件被清理后仍可查看保留期内任务记录。
- 列表行、详情头部和文件页共用上传交互；提交前重新读取文件数量，Excel / FileGDB / GeoPackage 已有物理文件时禁止新增上传并引导到原有整文件替换。同步上传错误和已选择文件保留在当前界面，后台解析结果持续刷新；不把成功提交表述为解析成功。不新增重试命令、不改变替换、删除和引用保护规则。

- 新建/修改文件数据集使用最长 760px 的单层白色抽屉，复用 `workspaceResourceTheme`：标题为类型图标、操作名称和类型文字；数据集信息与解析设置以细分隔线分区，不使用渐变、嵌套卡片、重复类型标签或步骤导航。正文和标签 14px、辅助说明 12px，单行控件及底栏按钮 36px，说明为 2～4 行并给字数提示留位；内容容器不足 480px 时字段单列，底栏操作始终可见。
- 类型下拉的选项和选中值均显示图标。14 种类型保持各自字段、默认值和提交结构：CSV/TSV 分隔规则、TXT/JSONL 编码与记录分隔、JSON 根路径、Excel 行设置、GeoJSON/GeoJSON Lines 的 EPSG、FileGDB 回退 EPSG、Shapefile 的 ZIP/DBF 编码及回退 EPSG；Parquet、Avro、GeoParquet、GeoPackage 保留自动识别说明。编辑时类型不可更改，解析设置锁定时全部解析控件只读，名称、目录和说明仍可编辑；CSV 分隔符不得通过显式 `disabled=false` 覆盖锁定状态。

- 与数据源复用公共目录组件的湖蓝样式：目录图标、选中状态、紧凑菜单及新建、修改、导入、删除浮层一致；样式归属目录模块，不依赖加载数据源页面。目录数据继续按 `DATA_SOURCE` / `FILE_DATASET` 隔离，权限、层级和导入导出语义不变。
- 列表采用独立筛选工具带和结果面板，查询、重置、刷新、解析队列和新建集中在工具带；窄容器允许换行。列为“数据集 / 说明、文件类型、数据规模、表就绪情况、更新时间、操作”。14 种类型在独立类型列和筛选选项中显示对应图标及完整名称；文件数量与表数量合并展示，名称与说明提供完整 Tooltip，不重复增加目录列。
- 复用全局中文无衬线字体与湖蓝控件，采用 72px 双行密度，名称 15px、正文 14px、辅助文字 13px；类型图标不叠加彩色底块。列宽按实际结果容器计算，表体最小宽度 900px，操作列 112px 固定右侧；上传、修改、删除三个图标直接展示，不设重复的更多菜单；删除仍需二次确认，列表与详情共用同一确认框，详情由名称进入。
- 目录“全部”数量读取无筛选列表接口的总数，包含未分类资源；不将根目录数量之和当作全量。表就绪情况区分“尚未上传”“已有文件但暂无数据表”“未就绪”“部分就绪”“全部就绪”，始终依据真实文件、表及就绪数，不据此推断解析任务运行或失败；处理详情保留在数据集详情和解析队列。

<a id="tables"></a>

## 表格与分页

- 管理页面的单行 Table 和 List 默认使用紧凑密度：表头高度 `40px`、数据行高度 `38px`、纵向内边距 `4px`，并统一使用 `size="small"`。Table 使用 `management-table`，List 使用 `management-list`，不得在普通页面重复声明相同行高。
- 名称/编码、名称/说明等双行身份信息，或包含 32～36px 资源图标时，使用共享 `ManagementListCell` 或 `management-table-comfortable` / `management-list-comfortable`，目标行高为 `52px`。只有健康状态、错误详情等确实需要多行内容的特殊表格才允许通过页面作用域覆盖为 `56～58px`。
- 紧凑密度规则只能作用于上述管理组件作用域，不得无边界覆盖所有 `.ant-table`、`.ant-list-item`，避免影响 Canvas、弹窗、Inspector 和其他专业工作区。
- 有分页的管理表格应始终在右下角显示分页，单页或数据较少时也不隐藏；默认显示总数和每页条数切换。无分页的静态或详情表格可例外。
- 翻页和修改每页条数应触发服务端查询；修改每页条数后应防止当前页码超出有效范围。
- 表头、分页保持可见，数据行在表体区域内部滚动。
- 单元格优先以“主信息 / 辅助信息”组合呈现：名称与编码、名称与说明、地址与目标、多个状态、日期与时间等相关信息应合并成一个语义单元，不得为每个字段持续增加独立列。
- 代码、URL、Topic、主机地址等使用纯文本等宽字体，不得渲染成带大面积灰底和边框的“禁用输入框”。可在点号、斜杠和连字符处换行，最多两行；被截断信息必须通过 Tooltip 可访问。
- 数值右对齐，空值统一显示为 `—`，日期时间使用项目统一格式。
- 主要列应指定合理宽度并按实际容器宽度分配；目录化列表不得将列宽预算按整个浏览器宽度计算。表格内容应优先压缩低频说明、合并语义字段和使用 Tooltip，而不是增加固定宽度。
- 以 1920×1080、浏览器 100% 缩放、主菜单和目录均展开为普通列表页的宽度验收目标。目录化列表的列宽预算不超过约 1360px，其他列表不超过约 1600px。不得用持续增大 `scroll.x` 处理字段过多问题，优先级依次为字段合并、两行展示、低频信息摘要与 Tooltip；目标分辨率下不得出现横向滚动。低于该宽度且确实无法容纳时，只允许表格内部横向滚动，不得造成页面横向滚动。

<a id="row-actions"></a>

## 行操作

- 操作列保持窄且稳定。普通静止行优先只展示“更多”图标；行 Hover 或键盘 `focus-within` 时可展示最多 2 个高频纯图标操作和一个“更多”入口。触屏或无法 Hover 的环境必须仍能通过“更多”访问全部操作。
- 常用操作使用 `type="text"` 的纯图标按钮，每个按钮必须同时提供 Tooltip 和能够识别具体对象的 `aria-label`。名称链接已经承担查看或进入编辑器功能时不得重复展示查看按钮。
- 超出两个的操作、低频操作、辅助操作和危险操作统一收入“更多”菜单，不得通过持续加宽操作列容纳全部操作。操作出现与隐藏不得引发行内容或列宽抖动。
- 删除等危险操作使用 danger 语义并必须二次确认；确认内容应包含具体对象名称，避免误操作。

<a id="drawer-forms"></a>

## 抽屉表单

- 普通资源的新建和修改优先使用 Drawer，保留列表上下文；仅在内容很少、需要强阻断确认或无法在抽屉中合理展示时使用 Modal 或独立页。
- 抽屉默认使用垂直表单；普通字段优先两列排列，强相关字段应分组，连接参数、高级选项等复杂内容使用明确分区。窄抽屉、长文本和复杂编辑器可使用单列。
- 抽屉底部操作固定右对齐，顺序统一为“辅助操作、取消、主操作”；保存、测试等异步操作必须展示 loading 并防止重复提交。

<a id="feedback"></a>

## 异步状态与反馈

- 路由代码加载使用立即可见的结构骨架，不使用裸文本或空白页。管理端保留侧栏、面包屑与顶部操作，内容区按列表、详情或工作台显示占位；已有菜单切换进度条与目标项反馈继续有效。首次验证登录使用品牌工作台骨架，校验失败仍保留明确错误与重试。门户在首页、目录和详情的代码加载阶段即显示真实页头与对应内容骨架，已有令牌验证期间的账户位置显示占位，避免闪现“登录”。骨架不伪造统计或完成百分比，装饰结构不进入辅助技术阅读与键盘顺序；减少动态效果偏好下关闭加载动效。

- 列表加载使用表格 loading；行级命令只允许当前行的对应操作进入 loading，不得因一行操作锁定整列或整页。
- 新建、修改、删除、测试等命令完成后必须给出明确的成功或失败反馈；错误信息优先使用统一 API 错误转换结果。
- 无数据时使用统一 Empty 状态。列表加载失败时应给出持续可见的错误信息和重试入口，不得只显示一次性消息后留下空白页面。

<a id="directories"></a>

## 目录树与列表

- 目录树和列表均占满可用高度并各自控制内部滚动，不得将滚动压力转移到整个页面。
- 所有目录和分类导航统一使用淡蓝紫渐变选中背景、蓝色强调文字和行内左侧 3px 蓝色标记；目录行使用约 4px 圆角及 600 字重。普通目录、“全部”/“未分类”快捷入口、平台 MCP 接口分类和资产门户业务领域卡片共享 `--ds-directory-selected-*` 变量。树节点选中效果覆盖整行，不能在文字区重复叠加标记；Hover 不得覆盖选中效果，数量仍保持紧凑宽度。
- 展开状态的目录面板默认宽度为 244px，允许在 200～360px 且不超过可用内容宽度 35% 的范围内拖动调整；各目录页共享最近一次宽度偏好，双击分隔线恢复默认宽度。收起状态固定为 48px、禁止拖动，重新展开时恢复上次宽度。拖动不得造成页面级横向滚动。
- 目录内容区水平内边距约 8px，根节点不增加额外层级缩进，子层级每级缩进控制在 14～16px；展开开关与目录图标应保持紧凑，并让“全部”“未分类”和一级目录形成清晰的左侧对齐关系。目录图标与文字必须垂直居中，二者保留约 5px 间距，不得紧贴或依赖字体基线碰巧对齐。
- 目录树采用细线右/下箭头表示收起/展开，配合 1px 淡蓝灰层级引导线；复用 Ant Design Tree 的 `showLine` 和叶节点连线，不展示叶节点文件图标。展开控件预留 24px 宽度，行内左侧留白 8px，避免箭头贴住选中标记；每级缩进 16px，行高 36px，根级叶节点不绘制悬空连线。
- 目录行高控制在 36～40px，目录名称只能单行展示，超长名称使用省略号并通过 Tooltip 提供完整内容，不得换行抬高行高。资源数量使用固定宽度、低对比度数字块，不能挤占名称的主要空间。
- 目录树默认提供“全部”和“未分类”入口；选择目录后直接刷新右侧列表并回到第一页。
- 采用左侧目录树、右侧资源表格的页面，右侧表格不得重复展示“目录”或“所属目录”列；资源详情和编辑表单仍可展示目录信息。
- 从目录化列表新建资源时，选中具体目录应默认代入该目录且允许修改；选中“全部”或“未分类”时默认未分类。选择父目录时，即使右侧列表包含其子目录资源，新资源仍默认归入当前选中的父目录。编辑已有资源不得被当前目录选择覆盖。
- 目录树节点在桌面端通过右键菜单管理，不为“更多”按钮预留宽度；聚焦目录名称后支持 `Shift+F10` 或菜单键，名称 Tooltip 提示操作方式。触屏设备通过紧凑的“更多”按钮打开同一菜单；菜单统一承载“新增子目录、修改目录、删除目录”。菜单只对有管理权限的用户开放，操作目标为触发菜单的节点，危险操作保留具体名称和二次确认。资源数量按实际需要显示，不再在 Hover 或选中时被操作按钮替换。
- 目录右键菜单使用浅色蓝紫面板、6px 圆角、26px 淡蓝图标底块及共享浮层阴影；桌面行高 36px，触屏至少 44px。Hover 和键盘聚焦使用淡蓝背景与左侧 2px 细线；删除项通过分隔线独立分组，并使用淡红图标底色、淡红交互背景与红色细线。样式限定在目录菜单浮层，避免影响其他下拉菜单。

## DSH 全局助手

聊天输入支持选择、拖拽附件和粘贴截图，发送前显示缩略图或文件卡片及上传状态，失败保留草稿并允许重试。历史附件支持认证预览与下载；模型不支持视觉时在输入区明确提示。数量、大小、格式与消息语义见[聊天附件](../design/dsh-chat-attachments.md)。

顶部“AI 助手”打开专业对话工作区，采用无模态 Drawer。默认窄模式为 `max(520px, 40vw)`，宽模式为 `80vw`，720px 及以下窗口占满；无遮罩、不禁用背景页面操作。宽窄偏好按登录用户保存在当前浏览器。路由切换保留会话和草稿；关闭只断开订阅，不取消任务。业务编辑 Drawer 仍使用既有交互，其层级高于助手。

宽模式左侧常驻 280px 会话管理 Panel，右侧保持当前对话；窄模式通过对话内的临时左侧 Panel 选择和管理会话，选择后自动收起，打开列表不应断开当前对话事件订阅。归档保留历史及工作文件，不使用“删除”文案。模型回答支持受限 Markdown，代码及表格仅在消息内横向滚动；具体交互、权限及恢复语义见[第四阶段设计](../design/dsh-plugin-phase-four.md)。


## 数据模型列表的资源工作区样式

- 数据模型目录复用数据源、文件数据集的湖蓝色目录组件，包括文件夹图标、目录菜单、编辑、导入和删除确认；目录资源仍按 MODEL 范围隔离。全部数量使用未筛选模型总数，包含未分类模型。
- 顶部放置查询、刷新与新建模型；空间不足时数据源与分层筛选收进“更多”。列表标题带模型图标，批量发布、刷新统计与导出结构保留在标题栏，并展示已选数量和取消选择入口。
- 使用共享资源主题、36px 常规控件与浅蓝灰表头。表格优先为模型名称和存储位置分配宽度，名称最多两行，编码和说明提供完整提示；统计成功采集时间收进提示，失败和不支持等状态直接显示。窄容器仅表格内部横向滚动。
- 四种创建方式、跨页选择、发布与统计数量上限、外部模型导出限制、行操作与权限条件维持原有逻辑，本次样式调整不改变后端行为。

- 模型行突出名称与分层：名称和编码相同则不重复展示，不同则保留编码副行；完整编码、分层及说明统一在名称旁的信息入口中可见（支持悬停、聚焦和点击）。存储位置使用实际数据库类型图标，无法取得类型时用通用存储图标；禁止根据数据源名称猜测类型。
- 模型列表采用稳定的 72px 双行布局：名称为主信息，差异编码、分层与 Schema 版本并排放在辅助行；空间不足时编码省略，完整编码与分层仍可通过说明入口查看。说明图标跟随名称，不单独漂浮在列末。存储位置两行分别显示数据源与物理表名，保留厂商图标及完整 Catalog / Schema / 表名提示。

- “状态 / 类型”列上方为生命周期圆点与文字，下方并列管理模式（托管表／外部表）和数据类型（空间表／属性表）小标签，避免挤占物理表名。类型采用单个双段信息标识：统一低饱和浅橄榄绿底、深灰绿文字、细轮廓与短竖分隔，左侧为管理模式，右侧为数据类型；无选中态、无按钮行为，不使用交互式分段控件。同一底色收拢两种维度，文字表达取值，避免多色小块与系统蓝青主色竞争，生命周期状态独立呈现。列表使用白底、轻分隔线和统一悬停／选中色；统计突出数值，未统计不得误显示为零。筛选、创建菜单应独立设置浮层宽度，完整呈现长文案，不能继承目录菜单的窄宽度。

- 创建模型选择来源或目标数据源时，使用带搜索、数据库类型筛选、服务端分页的单选窗口；文件数据集选择支持名称搜索、文件类型筛选及服务端分页，显示已就绪表数量，保持未就绪数据集不可选。选择窗口内的暂选只在确认后生效，取消或重复确认当前资源不重置创建表单；目标数据源仍限定具备存储用途的可用 JDBC 来源，编辑时保留原有资源资格规则。
- JDBC 源表按命名空间和关键字查询，查询结果分页展示，保留服务端 500 项截断提醒；文件逻辑表按名称／编码服务端搜索与分页。跨页、搜索及 JDBC 命名空间切换保留勾选并显示已选数量，允许清空选择；切换来源资源仍按原流程重置其相关草稿。共享文件表查询 Hook 的默认参数不变，仅模型导入流程显式传分页条件。

### 已调整资源与建模页面的统一密度
